# DDD 操作指引

先读运行时给出的当前交接；没有交接时读入口 index。再按当前任务读相关依据。实时目录见 DDD 面板，或用 `glob docs/*.md` 查看文件并读 frontmatter。旧磁盘清单可能过时，不用为它补条目或重排整张表。

如果没有激活且工具提示不是 DDD 项目，请用户点「初始化为 DDD 工作区」。不要自行写标记凑激活。用户已明确要求测试初始化的独立目录除外。

| 要做什么 | 操作 |
|---|---|
| 建受管文档 | `doc_new(role, title, summary, body, id)`；中文标题显式给 kebab-case id。默认 draft。 |
| 改正文或排序 | 先 `read` 目标，再用 `edit`；排序只改 frontmatter 的 order，无需同步清单正文。 |
| 改状态 | `doc_mark(id, status, basis?)`。sealed/void 要 reason；superseded 要 supersededBy。basis 是依据类型，不影响发布。 |
| 做交接 | 用 `doc_new(role: handover, status: authoritative, ...)` 一次发布；要保留草稿则传 draft，需选为当前入口时 `doc_mark` 发布。 |
| 更新已发布交接 | 直接 `edit` 原文；不用新建或重新发布。 |
| 提议归档 | `doc_mark(id, status: void, reason)`；文件搬运和恢复由用户在面板操作。被新交接取代的旧交接无需再标 void。 |
| 交付 | 成品放 `deliverables/`，再用宿主 `present` 呈现；没有另一个交付工具。 |

交接写清截至本次记录的状态、后续动作（可以是无）、关键约束，以及实际验证和未验证内容。不要求固定标题或七段，不为交接编造测试通过数。一条决定只更新实际归属的文档，不默认同步所有 spec、索引和旧交接。

**发布表示当前选用的接续入口，不表示工作已经全部完成。** 发布后发现漏项可以继续做工程工作并局部更新受影响的交接内容。不要假设自己能够预知“真的做完了”，也不用先把全库定稿、健康度归零再写交接。验证结论限于所验证的版本与范围。

目标文档未读或被外部修改时，按提示读取后重试；同会话成功自改不要求重读。`doc_new` 新建的内容已为本会话记账。子代理文档写入、decision 追加、evidence/instruction 保护和归档隔离沿用现有规则。

`doc_health` 与 `doc_handover_check` 仅在需要排查结构问题时显式使用，均为只读；不作为默认收尾步骤，不验证内容真实性或任务完成情况。出现部分发布失败时，按回执读取目标并对同一交接重试发布，不重复建一份。
