## 0. 这个项目究竟是什么（**先读这一节，否则你会做错方向**）

### 0.1 一句话

> **让 AI 在动手改项目文档之前，必须先读过该读的文档；「读没读」由插件记账并强制，不是靠提示词嘱咐。**

### 0.2 它解决的问题

AI 做长任务时，上下文会衰减。传统做法是"让 AI 自己记住"，但会忘。
这个项目的办法是：**把工程状态外置成文档，每轮只注入一个索引块，并用代码强制 AI 先读后改。**

灵感来源（用户原话）：

> 我以前跑过一个项目，它也是用的文档驱动开发的方法，但不是插件。
> 它就是 ai 写一大堆文档，改动了什么，新加了什么就往文档里写，
> 交接也是"写交接文档+重标置信度+调整阅读顺序"，**都是纯提示词的东西**。

那个项目叫**教练模式**（`coach-mode`，上一个插件）。它的实测数据是：

> 第二轮共 5 个会话，工具调用总计 5 次，其中**真正核查用户机器的只有 1 次**。

⇒ 由此确立**铁律 ①**：门禁必须是代码里的 `if`，不是提示词嘱咐。

**但用户后来指出这条路走过了头**（这是 M2.8 最重要的输入）：

> 但现在插件时不时就要 AI 严苛地去按某个规则做，**一不小心就碰壁**，
> 然后导致工作量增大，**很可能没法专注于工作项目本身了**。

⇒ 于是 M2.8 的核心工作不是"加判据"，而是**减摩擦**。

### 0.3 四个环节（插件怎么运作）

```
① adapters/probe.js      判断这个目录是不是 DDD 项目（找激活标记）
② docs/scan.js + adapters/registry.js   扫描 docs/，建注册表（内存缓存）
③ adapters/inject.js     每轮往系统提示词里注入一个「索引块」
④ adapters/guard.js → ctx.tools.guard()   真正拦 write/edit 的 if
```

**读没读**记在 `readSet`（**会话级、内存里的 WeakMap**），不落盘。
`edit` 成功 → 指纹变 → 该文档立刻变回"未读"（**铁律 7**）。

### 0.4 三条铁律（破坏了项目就失去意义）

| # | 铁律 | 为什么 |
|---|---|---|
| **1** | **门禁必须是代码里的 `if`，不是提示词嘱咐** | 教练模式已证明提示词约束会失效（5 个会话只有 1 次真核查） |
| **2** | **插件全局挂载，但作用域是项目** | 不能因为装了插件就让所有项目都被管 |
| **3** | **冻结决策要用户授权才能动** | `Q1–Q13` / `R1–R5` / `S1` / `S2` / `M1-Q` / `P` / `M2-Q` 都在 `文档驱动开发-架构评审与补充设计-v1.md` §6 |

> ⚠️ **但 M2.8 期间，用户在"减摩擦"这件事上给了一连串授权**（见 §2.3）。
> 那些授权改变了铁律 1 的**边界**：该强制的从"形状"收缩到"行为"。

### 0.5 术语

| 术语 | 意思 |
|---|---|
| **DDD** | 本文档里指**文档驱动开发**，**不是** domain-driven design |
| **受管文档** | `docs/` 下有合法 frontmatter 的 `.md` |
| **门禁** | `guard` 里那段 `if`，拦"没读过就改" |
| **标绿** | `doc_mark` 把 `status` 改成 `authoritative` |
| **指纹** | 文档正文的 sha256 前 8 位，用来判"你读过的是不是这一版" |
| **坟场** | `docs/_graveyard/`，被 `void` 的文档 |
| **H1–H9 / H-1~H-6** | 交接结构判据 / 文档健康度判据（见 §1.4） |
| **引擎步** | `read` + `doc_health` + `doc_handover_check`，**不产出任何文档内容**的调用 |

## 4. 坑（**这些坑我全踩过，别再踩**）

### 4.1 假注册表测不到真实现（**最贵的坑**）

`test/m28-fixes.test.js` 用**假注册表**，它自己实现 `isSelfWritten`。
**假的写对了、真的写错了 → 测试全绿 → 上线后 `doc_mark` 连挂 3 次。**

⇒ **凡是被测逻辑在真实注册表里，就必须用 `apply(ctx)` 真装配测**（见 `test/m28-selfwritten-real.test.js`）。

### 4.2 变异脚本的测试列表会漏（**第三次踩**）

`mutate-drill-fixes.mjs` 的 `runTests()` 有个**文件白名单**。
漏了某个测试文件 → 对应变异**必然 SURVIVED**，而"存活"会被误读成"断言太弱"。

**排查顺序**（交接 §4.5 的纪律，救了我 N 次）：
1. 先 `node _m23/verify-anchors.mjs` —— 锚点命中 0 次 = 变异**从没施加过**；
2. 再手动施加变异，看那个测试**是否真的红了**；
3. 只有确认"测试跑了但还是绿"，才是断言太弱。

### 4.3 断言"概念"比断言"位置"弱

我写 `assert.match(rendered, /别给交接留位置|泛指条目/)`，删掉回执那一段**仍然通过** ——
因为 ⓪ 前置那段也有「泛指条目」这个词。

⇒ **同一概念出现在两处时，必须分别断言。**

### 4.4 「验证器说通过」≠「它是真的」

第 29 轮 AI 写了 `0/0 通过`（零项被验证），**H4 判它合格**。
是 AI 自己发现并报告的：「校验通过 ≠ 内容为真」。

⇒ 你写测试时，**别只断言"通过了"，要断言"它真的做了那件事"**。

### 4.5 改文案后立刻跑 `verify-anchors.mjs`

我改 H4 正则后，一条变异的锚点**静默失效**（出现 0 次），而它此前一直显示 CAUGHT —— **那个 CAUGHT 是假的**。

### 4.6 我写的提示词会被字面执行

第 29 轮我写「别给交接留位置」，第 30 轮 AI 把工具自动登记的那行 `handover-1` **也删了** → H-3 报错。

⇒ **写「别做 X」必须同时说清「但 Y 要做」**，否则 AI 会把 Y 一起干掉。

### 4.7 环境坑

| 坑 | 解法 |
|---|---|
| `git` 通过管道捕获输出 → `Access to the path '\\.\pipe\LOCAL\...' is denied` | 用 `Start-Process -RedirectStandardOutput`，或直接 `git ... 2>&1`（`danger-full-access` 下可以） |
| `node --check` 通过管道失败 | 同上 |
| 临时重定向目标被 `git add -A` 收进提交 | 放 `_m28/`（已被 `.gitignore` 挡住），或立刻删 |
| 会话日志是 `.zstd` | `node _m23/decode-session.mjs <x.zstd> <out.jsonl>` |

### 4.8 测试之间的相互污染

`--test-isolation=none` 让所有测试文件共享进程。**顺序不同，红的测试可能不同**。
我遇到过「H4 词表」那条时红时绿，根因是**切片边界写错**（`indexOf("].join('')")` 会命中数组内部的）。

⇒ 用字符串定位代码块时，边界必须**足够独特**（比如 `'\n].join(\'\')'` 顶格）。

> **这个项目前 8 轮在"加判据"，M2.8 在"减摩擦"。**

>
> 每次你想加一条判据时，先问自己：**它拦住的，和它制造的返工，哪个更贵？**
