## 2. 更关键：`inject` **根本不校验**包名

`dsh-client-modules/lib/index.js`（宿主半侧）里，`dsh.client.inject` 只被搬进 graph row：

```js
meta: {
  clientPath: join(dirname(pkgPath), clientRel),
  manifestPath: pkgPath,
  ...decl.inject !== void 0 ? { inject: decl.inject } : {},
  external: decl.external ?? [],
  immediately: decl.immediately === true
}
```

它**只做类型校验**（`optionalStringArray`：必须是字符串数组），**没有任何一处把它解析成包/行/服务**。

消费端在浏览器侧（`src/client/system.ts` L275–278）：

```js
for (const packageName of row.inject) {
  const dependency = this.graphRows.get(packageName)
  if (dependency !== undefined) await this.arriveDependency(row.id, dependency, [], visited)
}
```

**查不到对应的 graph row 就 `undefined` → 直接跳过，不抛。**

> ⇒ **即使 inject 写错，宿主也不会起不来。** 这条怀疑线到此彻底作废。

## 3. 真正会抛的是 `external`，不是 `inject`

两条硬抛点（`system.ts`）：

| 位置 | 条件 | 抛什么 |
|---|---|---|
| `makeRequire`（同步 require） | `spec` 既不在 seed 表、也没 materialize、也没注册 factory | `client-modules: require("...") missed the module table …` |
| `arriveGraphRow` → `arrive` | 拿不到脚本 / 脚本执行了却没注册该 id | `client-modules: could not load "..."` |

**我们的声明里没有 `external`**，产物里唯一的运行时 require 是 `require('react')`（已 `grep` 过 26 518 B 的 `lib/client.js`，只有这一个 specifier），而 `react` 在浏览器壳的 `staticModules` 种子里：

```js
function WJ(){return{react:rS,"react/jsx-runtime":aS,"react-dom":fS,"react-dom/client":mS,
  "@deepseek-ai/cordis":jC,zod:tN,"@tanstack/react-virtual":cN,
  "@deepseek-ai/dsh-client-store":NN,"@deepseek-ai/dsh-client-ui-slots":RN,
  "@deepseek-ai/dsh-client-ui-primitives":MK,"@deepseek-ai/dsh-client-ui-dockkit":RJ}}
```

> ⇒ `require('react')` 命中种子，**不走 external 校验、不依赖 inject 顺序**。

## 4. **「web boot: N entry did not activate」是浏览器说的，不是宿主说的**

在 asar 全量文本里 `grep "web boot"`，命中 6 处，其中拼那句话的**只有一处**：

`dsh/node_modules/@deepseek-ai/dsh-web-frontend/dist/assets/index-ghOpC9uV.js`（前端 bundle）：

```js
const n=c=>UJ.has(c), o=i.filter(({name:c})=>n(c)).length;
if(o>0){ ... throw new Error(`web boot: ${String(o)} required ${a9(o)} did not activate\n${c.join('\n')}`) }
const l=i.map(({name:c,reason:d})=>`${c}: ${reason}`);
r(`web boot: warning: ${String(i.length)} ${a9(i.length)} did not activate\n${l.join('\n')}`)
```

单条失败项的格式是 `` `${c.options.name}${required?' (required)':''}: ${reason}` `` ——
**这正好对应 `@local/ddd: failed` 的形状**（`reason` 由 `HJ()` 拼成 `failed: <error>` 或直接 `"failed"`）。

### 4.1 它怎么变成 `crash-*-web-boot.log` 的（**这条闭合了整条链路**）

1. 浏览器里 `entry.run(reportFailure)` 抛 → `main.ts` 的 `reportFailure` 调 `desktop.failed(message)`；
2. Electron IPC `dsh-desktop:boot-failed` → `lib/main.js` L20822：`reportFatal(new Error(message), "web-boot")`；
3. `reportFatal` → `writeCrashReport(app.getPath('logs'), ...)`，文件名正则：
   `crash-<ISO>-<host|web-boot|renderer|main>.log`。

> ⇒ **`-web-boot` 后缀是「这条消息来自渲染进程的 boot 审计」的标签**，
> 不是「宿主 `clientModules` 服务构造失败」的证据。
> 交接与事故记录把这两件事当成同一件，**这是诊断走偏的开始**。

### 4.2 但日志文本的形状仍对不上（**必须拿原文**）

| 可能来源 | 实际会打印的文本 |
|---|---|
| 浏览器 UJ 分支（required 命中） | `web boot: 1 required entry did not activate` |
| 浏览器 warning 分支 | `web boot: warning: 1 entry did not activate` |
| 宿主 `activationDiagnostic` | `web boot: warning: 1 entry did not activate` |
| 宿主 `startupDiagnostic` | `web boot: startup failed: 1 required plugin did not activate` |

事故记录里写的是 **`web boot: 1 entry did not activate`** ——
既缺 `required`，也缺 `warning:`。**两种分支都拼不出这一行。**

所以这一行**很可能是转述**（少了中间那个词）。在拿到原文之前，
**不应再从这句的形状反推到底是哪一支**。

> ⚠️ `UJ`（required 集合）是**写死的 7 个官方包**：
> `dsh-client-modules / dsh-api-session-controller / dsh-client-ui-renderer /
> dsh-client-ui-layout / dsh-client-ui-session / dsh-client-ui-chat / dsh-client-ui-sidebar`。
> **`@local/ddd` 不在里面** ⇒ 单靠 @local/ddd 一项失败，只能走 **warning** 分支，
> **不足以让 `entry.run` 抛错、更不足以产生 crash 日志**。
> 这是「必须拿原文」的第二条理由：原文里应该还有**别的**失败项，或者根本不是这条路径。
