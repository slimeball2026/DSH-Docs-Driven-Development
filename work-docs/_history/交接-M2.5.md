## 0. 这个项目是什么（**先读这一节**）

> 这一节被漏过三次（三个不同作者），所以系统强制保留。
> **完整版见 `交接-M2.3施工者.md` §0**（含用户原始设想、评审三处修正、术语表）。

**一句话**：

> **让 AI 在动手改项目文档之前，必须先读过该读的文档；「读没读」由插件记账并强制，不是靠提示词嘱咐。**

这是一个 **DSH 全局插件**，名字叫「文档驱动开发」（DDD，**不是**领域驱动设计）。

### 0.1 它具体怎么工作

不是"提醒模型去读文档"，而是四件事拼起来的**约束器**：

| # | 环节 | 落点 | 一句话 |
|---|---|---|---|
| 1 | 激活判定 | `adapters/probe.js` | 探不到 `AGENTS.md` 的 `<!-- ddd:index` 或 `docs/` 下合法 frontmatter → **整个插件对该项目 no-op**，绝不误伤普通仓库 |
| 2 | 扫描建注册表 | `docs/scan.js` + `adapters/registry.js` | 把 `docs/**.md` 读成条目（meta / 指纹 / 是否有 error）。**坟场永不进索引** |
| 3 | 索引注入 | `adapters/inject.js`（走 `systemPrompt.context()`） | 每轮往模型上下文里塞 `【门禁】`/`【预算】`/`【项目】`/`【已读】`/`【未读】`/`【禁止执行】`/`【文档异常】` |
| 4 | **门禁** | `adapters/guard.js`（`ctx.tools.guard()`） | 模型调 `write`/`edit` 打 `docs/` 时**按路径判**：要改的那份读过没？role 允许写吗？**没读过就拒绝** |

**关键在 3 与 4 的分工**：3 只是"让人看见清单"，**4 才是那个 `if`**。
只有 3 就是提示词嘱咐（教练模式已证明会失效），只有 4 就是莫名其妙被拒。

### 0.2 用户的原始设想（**为什么会有这个项目**）

用户最初想要一个**可视化**工具：DSH 右栏三个分区（工作区树状图 / 交付成品网格 / 坟场），
配「阅读顺序」与「文档置信度」（绿/黄/红 + 原因）。

核心流程：**AI 不直接开工** → 问清需求 → 规划 → 产出文档 → **按文档施工** → 交接时更新阅读顺序与置信度。

> 最有价值的一句：「**更建议写交接文档交给下一个会话**」。
> 这不是功能，是**对「AI 会话是有限资源」的承认**。

### 0.3 评审之后，项目变成了什么

架构评审（`文档驱动开发-架构评审与补充设计-v1.md`）做了三处根本修正：

| 原设想 | 修正后 | 为什么 |
|---|---|---|
| 先做可视化 | **先做约束器**，M0/M1/M1.5 零 UI | UI 解决"看得见"，解决不了"AI 会不会照做"。后者才是价值 |
| 置信度写在散文里 | **frontmatter 元数据是真源**，图是渲染 | 手写散文索引必然漂移 |
| 插件做成 preset | **全局插件，按项目激活**（S1） | preset 会让标准模式看不到它，**且门禁能被"切个模式"绕过** |

> **M2 是第一次让"外部观察者"能看见这个插件的内部状态。**
> 所以 M2 的 UI 如果显示了**错的数据**，比没有 UI 更糟 —— 它会把"错误的信任"可视化。
>
> 这句话在 M2.3 被反复应验：依据文档指向了错误的文件、勾跨会话泄漏、
> 两个绿圆分不清 —— 每一个都是"把错误的信任可视化"。

### 0.4 三条铁律

| # | 铁律 | 破坏了会怎样 |
|---|---|---|
| 1 | **门禁必须是代码里的 `if`，不是提示词嘱咐** | 退化成软约束（教练模式已证明会失效） |
| 2 | **全局挂载，项目级生效**（S1，不做 preset） | preset = 标准模式看不到 + 门禁能被切模式绕过 |
| 3 | **Q1–Q13 / R1–R5 / M1-Q1–M1-Q9 / P1–P14 / M2-Q1–M2-Q6 已冻结** | 改冻结决策必须有用户授权记录 |

### 0.5 术语

| 词 | 含义 |
|---|---|
| **DDD** | 本插件名。**不是**领域驱动设计 |
| **受管文档** | `docs/` 下带合法 frontmatter 的 `.md` |
| **unmanaged** | `docs/` 下完全没有 frontmatter 的 md。不进索引、不报异常，但可写 |
| **激活标记** | T1: 合法 frontmatter；T2: `AGENTS.md` 含 `<!-- ddd:index`。**没有标记 → 插件 no-op** |
| **坟场** | `docs/_graveyard/`，只读、不进索引、**平铺**（不递归） |
| **M0-5 红线** | 索引块**不得含快变量**（时间戳 / 轮次 / 百分比）。内容一变宿主就 append 一条新历史消息 |
| **双注册** | Q7 = C：`sidebar.panellist`（左栏入口行）+ `main`（主栏整页）。**少一个就白做** |
| **root scope / session scope** | 主栏席位无会话（拿不到 cwd、预览必抛）；右栏页签有会话（自动有 cwd、能预览） |
| **readSet** | 「本会话读过什么」——host 侧 `WeakMap`，**内存态**，宿主重启归零 |
| **勾（✓）** | 阅读顺序条上的已读标记。**只增不减、按会话隔离**，与门禁实时读数分离 |

## 4. 坑（**按代价排序，必须看完**）

### 4.1 本轮最贵的三个坑

| # | 坑 | 代价 | 怎么避免 |
|---|---|---|---|
| **1** | **框架 standard props 里的 `useXxx` 都是 React hook** | 切会话时**整个右栏被炸空**，用户实测才发现 | 只能在组件顶层**无条件**调用。放进 `useMemo`/`if`/`&&` 都会炸。详见 `M2.3-事故记录-右栏被炸空.md` |
| **2** | **变异存活时，先怀疑"测试没跑到"** | `memory-key-global` 连续两轮存活，我先去加强断言（**白做**），真因是 `runTests()` 只跑了一个测试文件 | 或**断言恒真**（`doesNotThrow` 遇到内部 try/catch 永不失败）。排查顺序：**先确认覆盖，再确认断言** |
| **3** | **`BAD-ANCHOR` 意味着"你以为在测的东西根本没测"** | `_rv/mutate.mjs` 曾经 2 个锚点缩进错一层，导致「CAUGHT 29」名不副实（实际只有 29/31 真跑过） | 锚点必须**逐字**匹配源码（含缩进）。看到 BAD-ANCHOR 当 error 处理 |

### 4.2 其它必须知道的

| # | 坑 | 怎么避免 |
|---|---|---|
| 4 | **组件之间互引**（`session-tab.tsx` ↔ `index.tsx`） | 用参数注入打断环（`wiring.makeController`）；共享逻辑放**中性文件**（`visibility.ts`） |
| 5 | **插件抛错连累宿主 UI** | **每个插件 UI 都必须自带错误边界**（见 `TabErrorBoundary`） |
| 6 | **`.js` 里写 TS 语法**（`interface` / `as any` / `: string`） | Node 的类型剥离**只处理 `.ts`**。本轮撞了 6 次 |
| 7 | **静态断言把注释也算进去** | 先剥注释再断言：`text.replace(/\/\*[\s\S]*?\*\//g, '')` |
| 8 | **`console.warn` 与 `ctx.logger.warn` 是两条通道** | 产物级验证比较"跑前/跑后"的条数，别去 logger 里找 |
| 9 | `tsdown` 入口是 `dist/run.mjs`（不是 `.js`） | `node node_modules/tsdown/dist/run.mjs` |
| 10 | **改 `inject` 必须重启宿主** | 刷新看不到页签，误以为功能坏了。与 `M2-施工记录-宿主重载真相.md` 一致 |
| 11 | 只查 asar 根 `node_modules` | 真宿主在 `dsh/node_modules/` |
| 12 | **cwd 拿不到就留空，绝不猜** | 猜错会显示**别的项目**的门禁读数 —— 比不显示更糟 |

## 5. 关键设计决定（**别随手改**）

| # | 决定 | 理由 |
|---|---|---|
| 1 | 阅读顺序条数据源是 `required`，**不是 `all`** | `required` = AI **被强制**要读的，语义最准（用户 W3 拍板） |
| 2 | **client 绝不重排顺序** | 顺序真源在 host `buildIndex()`。再排一次会造出**第二套顺序** |
| 3 | 条挂在 `BodyWith` 的 footer，**不是** `BoardPage` 里平铺 | 只有 `BodyWith` 知道"快照有没有到手"。挂外面会显示**假的 0/0** |
| 4 | 页签**不声明 `patterns`** | 我们是 `extension` 档（最高）。声明了会**抢走 `documentpreview` 的所有文件预览** |
| 5 | 页签三处注册的 key **必须逐字一致** | 不一致 = 点开页签**一片空白，且不报错** |
| 6 | `✓` **只增不减**，按会话隔离 | 用户两次澄清：①接手时读完是收尾状态；②换会话要清空 |
| 7 | `gate.read` **必须实时**，一行没动 | 改了文档就要重读 —— 这是不变量 |
| 8 | 绿色**专属于置信度**，已读用 `✓` / 空心圆 | 用户指出两个绿圆分不清 |
| 9 | `basisDoc` **只扫 §5**，且校验受管文档 | 扫全文会把 §3 提到的**交付物** `report.md` 当成依据 |
| 10 | 轮询 5 秒 + **后台标签页零请求** | 原设计"不轮询"的理由成立，但覆盖不了"一直盯着看" |

## 9. 最后一句

M2 的两个需求都落了地，M2-3 判据（点开文档能预览）在会话右栏页签里通过了。
但这一轮真正的收获不是"做完了"，而是**发现我的测试体系有个大洞**：

> 再动代码。你会发现我没有发现的东西 —— 前四轮都是这样。
