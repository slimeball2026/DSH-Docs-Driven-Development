## 0. 这个项目是什么（**先读这一节**）

> 这一节被漏过三次（三个不同作者），所以保留强制。

**一句话**：

> **让 AI 在动手改项目文档之前，必须先读过该读的文档；「读没读」由插件记账并强制，不是靠提示词嘱咐。**

这是一个 **DSH 全局插件**，名字叫「文档驱动开发」（DDD，**不是**领域驱动设计）。

| # | 环节 | 落点 | 一句话 |
|---|---|---|---|
| 1 | 激活判定 | `adapters/probe.js` | 探不到 `AGENTS.md` 的 `<!-- ddd:index` 或 `docs/` 下合法 frontmatter → **整个插件对该项目 no-op** |
| 2 | 扫描建注册表 | `docs/scan.js` + `adapters/registry.js` | 坟场永不进索引 |
| 3 | 索引注入 | `adapters/inject.js` | 每轮塞 `【门禁】/【预算】/…`，**只让人看见** |
| 4 | **门禁** | `adapters/guard.js` | 模型调 `write`/`edit` 打 `docs/` 时按路径判，**没读过就拒绝** |

**关键在 3 与 4 的分工**：3 只是"让人看见清单"，**4 才是那个 `if`**。

**三条铁律**：门禁必须是代码里的 `if`；全局挂载、项目级生效（S1，不做 preset）；冻结决策不擅自改。

## 3. 本轮最重要的两件事（**都会再犯，请记住**）

### 3.1 我修了一个自己造成的、把整个右栏炸空的事故

**症状**：切到新会话 → 右栏纯空；**切回原会话也不恢复**。

**真因**：把 `useSessions`（框架注入的 **React hook**）放进了 `React.useMemo` 的回调里。
渲染期有条件调用 hook → hook 顺序变化 → React 抛错 → 错误边界卸载整棵右栏子树。

**完整复盘见 `M2.3-事故记录-右栏被炸空.md`**（含 7 条教训）。

**如果你只记一条**：

> **"整个面板变空" ≠ 数据问题。**
> 判断口诀：**如果另一格也空了，就是渲染期抛错** —— 去查 hook 与 render 逻辑，别查接口。

### 3.2 用户抓到一个我测不出来的视觉歧义

旧版 chip 是 `1 🟢 read-order ○`，其中 `🟢` 是**置信度**、后面的圆是**已读**。
而我写的图例是「绿点 = AI 读过」——**把置信度说成了已读**。
更糟的是已读时我画**实心绿点**，于是变成两个绿圆。

**已修**：已读改用 `✓`（形状），未读用空心圆，**绿色从此专属于置信度**，
图例改成 `🟢 置信度 ｜ ✓ = AI 读过`。

## 4. 坑（按代价排序，本轮新增）

| # | 坑 | 代价 | 怎么避免 |
|---|---|---|---|
| 1 | **框架 standard props 里的 `useXxx` 都是 hook** | 整个右栏被炸空，用户实测才发现 | 只能在组件顶层**无条件**调用。放进 `useMemo`/`if`/`&&` 都会炸 |
| 2 | **`BAD-ANCHOR` 意味着"你以为在测的东西根本没测"** | 「CAUGHT 29」名不副实，实际只有 29/31 条跑过 | 锚点缩进必须逐字匹配源码。看到 BAD-ANCHOR 当 error 处理 |
| 3 | **组件之间互引** | `session-tab.tsx` ↔ `index.tsx` 循环依赖，单文件打包下"碰巧能跑" | 用参数注入打断环（`wiring.makeController`） |
| 4 | **插件抛错连累宿主 UI** | 我的页签坏了，整个右栏跟着消失 | **每个插件 UI 都必须自带错误边界** |
| 5 | **`.js` 里写 TS 语法** | 本轮撞了 5 次，每次只报一行 | Node 的类型剥离**只处理 `.ts`**。`.js` 里只能纯 JS |
| 6 | **变异本身写错，却以为是测试漏了** | 一度误判 | 变异必须**真改坏**。存活时先怀疑变异 |

```
registry.entries
  → primaryHandoverOf()      只认 role:handover，取 order 最小（同 order 按 id，稳定）
  → registry.textOf(id)      扫描时缓存的全文（**同步**，不读盘）
```

| 字段 | 取法 | 取不到时 |
|---|---|---|
| `nextStep` | §3「下一刀」**第一条未完成**的条目 | 空串 → 看板不显示那一行 |
| `basisDoc` | 全文第一个 `` `xxx.md` `` + 可选 `§x` | `null` → 看板不显示那一行 |

**三条"刻意不接受"**（都是为了不制造假信号）：
1. 带 `~~删除线~~` / `✅` 的条目跳过（交接文档用它标"做完了"）。
2. 裸文件名不算引用，**必须反引号**（散文里到处是文件名）。
3. 没有 `.md` 的代码路径不算文档。

**一条不编造**：`basisDoc` 引用的文档若不在注册表里，指纹**留空**。

#### 5.2.2 两个 BAD-ANCHOR 的真因（**这个坑很朴素**）

**锚点缩进写错了一层。** 源码里是

```js
      push(
        'H9',
        'warn',
```

`'H9',` 那一行缩进 **8 空格**（在 `push(` 内层），而变异里写的是 6 空格。
`indexOf` 找不到 → 锚点"出现 0 次" → **那条变异从来没真正施加过**。

> 所以「CAUGHT 29」名不副实：**31 条里只有 29 条真的跑过**。
> 修好缩进后：**CAUGHT 31 / SURVIVED 0 / BAD-ANCHOR 0**。
>
> **教训**：`BAD-ANCHOR` 不是"少覆盖两条"这种小事，
> 它意味着**你以为在测的东西根本没测**。看到它就该当成 error，不是 warning。
