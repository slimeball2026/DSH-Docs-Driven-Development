## 0. 这个项目是什么（**先读这一节**）

> ⚠️ 这一节被漏过三次（三个不同作者），所以它由系统强制：索引块的 `【项目】` 行 + **H9** 判据。
> ⚠️ **M2.2 交接的第一版又漏了一次** —— 我只留了「一句话」，把下面 0.2 / 0.3 / 0.4 三节
> （原始设想、评审后的三处修正、切片地图）压缩掉了。**那三节恰恰是"这个项目在干什么"的主体。**
> 用户当场指出。所以现在补回来，并把这句记录留在这里，让下一位知道这条判据真的在起作用。

**一句话**：

> **让 AI 在动手改项目文档之前，必须先读过该读的文档；「读没读」由插件记账并强制，不是靠提示词嘱咐。**

这是一个 **DSH 插件**，名字叫「文档驱动开发」（DDD，**不是**领域驱动设计）。

### 0.1 它具体怎么工作（**你改代码前要建立的机械图景**）

不是"提醒模型去读文档"，而是四件事拼起来的一个**约束器**：

| # | 环节 | 落点 | 一句话 |
|---|---|---|---|
| 1 | **激活判定** | `adapters/probe.js` | 向上探 `AGENTS.md`（含 `<!-- ddd:index`）或 `docs/` 下合法 frontmatter。**探不到 → 整个插件对该项目 no-op**，绝不误伤普通仓库 |
| 2 | **扫描建注册表** | `docs/scan.js` + `adapters/registry.js` | 把 `docs/**.md` 读成条目（meta / 指纹 / 是否有 error）。**坟场永不进索引** |
| 3 | **索引注入** | `adapters/inject.js`（走 `systemPrompt.context()`） | 每轮往模型上下文里塞一段清单：`【门禁】`/`【预算】`/`【项目】`/`【施工】`/`【已读】`/`【未读】`/`【禁止执行】`/`【文档异常】` |
| 4 | **门禁** | `adapters/guard.js`（`ctx.tools.guard()`） | 模型调 `write`/`edit` 打 `docs/` 时，**按路径**判：要改的那份读过没？role 允许写吗？**没读过就拒绝** |

**关键在 3 与 4 的分工**：3 只是"让人看见清单"，**4 才是那个 `if`**。
只有 3 就是提示词嘱咐（教练模式已证明会失效），只有 4 就是莫名其妙被拒。
M0 的验收就是「读完前拒绝、读完后放行」这一对。

### 0.2 用户的原始设想

用户最初想要一个**可视化**工具：DSH 右栏三个分区（工作区树状图 / 交付成品网格 / 坟场），
配「阅读顺序」与「文档置信度」（绿/黄/红 + 原因）。

核心流程：**AI 不直接开工** → 问清需求 → 规划 → 产出文档 → **按文档施工** → 交接时更新阅读顺序与置信度。

> 最有价值的一句：「**更建议写交接文档交给下一个会话**」。
> 这不是功能，是**对「AI 会话是有限资源」的承认**。

### 0.3 评审之后，项目变成了什么

架构评审（`文档驱动开发-架构评审与补充设计-v1.md`）做了三处根本修正：

| 原设想 | 修正后 | 为什么 |
|---|---|---|
| 先做可视化 | **先做约束器**，M0/M1/M1.5 零 UI | UI 解决"看得见"，解决不了"AI 会不会照做"。后者才是价值 |
| 置信度写在散文里 | **frontmatter 元数据是真源**，图是渲染 | 手写散文索引必然漂移 |
| 插件做成 preset | **全局插件，按项目激活**（S1） | preset 会让标准模式看不到它，**且门禁能被"切个模式"绕过** |

这也解释了 M2 为什么要做 UI，以及为什么 UI 显示错数据比没有 UI 更糟：

> **M2 是第一次让"外部观察者"能看见这个插件的内部状态。**
> 所以 M2 的 UI 如果显示了**错的数据**，比没有 UI 更糟 ——
> 它会把"错误的信任"可视化。这正是 M2-Q1 要求先把 M1.5 修完的原因。

### 0.6 现场事实（**这一轮更新过**）

1. **工作区根 `DDD插件施工\` 不是 DDD 项目** —— 没有 `docs/`、没有 `AGENTS.md`。
   所以 `doc_new` / `doc_mark` / `doc_health` / `doc_handover_check` **在本工作区里全部不可用**
   （返回 `no-project-root`）。本轮文档全是**手写 frontmatter** 的。
   真正是 DDD 项目的：`dogfood/`、`_m1-probe/`、`_m1-drill/`、`_review/proj-a/`、`_m15/live-proj/`、`_m15-live2/`。
2. **改 `apply()` 必须重启**；改 `core/*.js` 这类被 import 的模块，HMR 会热替换。
   区分标准：**`inject` 声明、`ctx.effect` 注册、模块顶层闭包捕获 → 要重启；纯函数改逻辑 → 不用。**
3. **`dsh.client` 是"全有或全无"的开关**：组合失败一次 → `clientModules` 服务整体不存在
   → 声明它的 entry 全部 `failed` → **宿主起不来**。这是 M2 那次事故的直接原因。
4. **外部 HTTP 探测其实能区分"路由在/不在"**（本轮订正交接 M2 的说法）：
   注册过的 exact 路径用错方法 → **405**；不存在的路径 → **401**（认证发生在路由匹配之前）。
   **405 vs 401 是零成本的"路由活着"判据**，比 `%TEMP%\_m2-route-probe.json` 更硬。

| 词 | 含义 |

## 1. 我的意图

**本项目是「文档驱动开发」（DDD）插件 —— 一个让 AI 改文档前必须先读过文档的约束器。**
（完整的来历、原始设想、切片地图见 §0；这里只说我这轮想干什么，以及为什么是这些而不是别的。）

用户 2026-11-13 拍板了三件事（本次施工的授权）：

| 问题 | 用户的选择 |
|---|---|
| 第一刀走哪条路 | **路线 A：M2-E 物理移动**（不依赖 client、不重启宿主） |
| 归档原路径元数据存哪（SPEC R-6） | **写进被归档文件自己的 frontmatter**（不是 `_artifacts/graveyard.json`） |
| 重启授权 | **选 2：授权重启，但每次先备份 + 单变量 + 失败立刻回滚**，并要一个**外置的回滚程序** + 故障时去哪启动它 |

我的意图：**把 M2 里唯一还缺的"写"操作补齐，让 M2-5 从"501 未装配"变成"真的能归档"，并且每一层判据都能自己重跑。**

**为什么是这个而不是 UI**（这一条决定你接下来该做什么）：本项目从 M0 起就在证明一句话——
「约束器的价值在**代码里的 `if`**，不在**看得见**」。M2 加 UI 是为了让**人**看见，
但 UI 一旦显示错数据，它会把**错误的信任**可视化，比没有 UI 更糟。
所以路线 A 优先于路线 B 不是取舍工期，是取舍**风险次序**：
先把"能自动验的判据"做满（归档的物理移动可以被 851 条测试和真磁盘探针钉住），
再动"只能靠重启验"的那半侧（client bundle，一次失败就让宿主起不来）。

我执行成的一条原则（继承自 M2 施工者，值得你继续）：

> **每一条数据都要能追到它的真源。追不到就留空 —— 留空比显示一个猜的数字好。**
> 本轮落成三处：还原时没有 `archivedFrom` 就**不猜**路径；失败形状**必须与成功同形**（不许让 UI 炸在 `undefined`）；
> 归档只认 `void`（不许把 `superseded` 当待归档）。

> ⚠️ **这条原则也回头看了一次我自己**：我在 `write-engine.ts` 里统一了失败形状，
> **却漏了 `index.js` 的两处早退** —— 是新写的一个探针抓到的，不是"我觉得对"抓到的（详见 §4 坑 #1）。
> **这就是本项目对"判据"的定义：能重跑、能证伪、能抓到自己。**

### 3.2 路线 B：client 半侧（**这是 M2 剩下的唯一大石头**）

**先读 `M2-待办-客户端未启用.md` §三。** 但**注意我这一轮给的一个新怀疑**：

> 交接 M2 的反证是「注入 `@deepseek-ai/dsh-client-ui-sidebar` 合法，因为 `dsh-cuigengji-plugin` 就注入了它」。
> **但 cuigengji 是 `enabled: false`，不在 profile 的 `bundles` 里 —— 它的 `dsh.client` 声明从来没有参与过一次组合。**
> 用一份"从未被组装过的声明"去反证"这个声明合法"，逻辑上是空的。

`dsh-client-modules` README 明写组合阶段会「**拒绝畸形请求、缺失提供方**」：
`dsh.client.inject` 里每个请求必须解析到「某个动态包 row」或「静态平台表里的完全匹配键」。

**所以真因很可能是 inject 里有一个解析不到提供方的包名** —— 那不是 declaration malformed，
也不是 bundle missing，而宿主只报这两类，所以我们一直对不上号。

**这条可以在不重启、不碰宿主的情况下先查**：`app.asar` 是 213 MB 的归档，但头部就是完整目录 JSON，
写个只读脚本就能列出 `node_modules/@deepseek-ai/` 下真实存在的包名，直接看那个名字到底在不在。
**这应该是走路线 B 的第一步，而不是先改 `lib/client.js` 做三次试验。**

**profile 里 5 个插件的 `dsh.client.inject` 实况（已抄下来，可作对照）**：

| 插件 | inject |
|---|---|
| `dsh-context` | api-remotes / client-connection / client-locale / ui-conversation / ui-settings / ui-sidebar-right |

## 4. 坑（**这一轮新踩的，按代价排序**）

| # | 坑 | 代价 | 怎么避免 |
|---|---|---|---|
| 1 | **在 `write-engine.ts` 里统一了失败形状，却漏了 `index.js` 的两处早退** | 一个真 bug：用户在非 DDD 项目里点归档 → 面板炸在 `undefined.length` | 形状一致性要**在"所有返回点"上验**，不能只在被抽出来的那个 helper 里验。`probe-routes-wired.mjs` 抓到了它 |

| 3 | **变异锚点不唯一**（`if (sourceDeleted !== true) {` 在归档/还原各出现一次） | BAD-ANCHOR，一条变异白做 | 锚点带上**下一行注释**；跑完看 BAD-ANCHOR 计数 |
| 4 | **断言没锚定作用域**（`/archivedFrom/` 命中两条不同失败） | 变异 `W-restore-no-origin` **存活**（14 个里唯一） | 断言要含**这一支特有**的半句 + `doesNotMatch` 另一支 |
| 5 | **救砖脚本自己会变成砖**：`Set-Content -Encoding UTF8` 在 WinPS 5.1 写 BOM | `package.json` 带 BOM → 宿主和 `decoupling.test.js` 都解析失败 | 用 `[System.IO.File]::WriteAllText` + `UTF8Encoding($false)`，并在末尾**回读校验 BOM** |
| 6 | **救砖脚本把"可选步骤"放在"必要步骤"之前** | 没有 profile 写权限时，**连工作区那步能做的都没做**就退出了 | 顺序：**能做的先做完**，做不了的降级 WARN 并说清后果。加 `-DryRun` 才能安全演练 |
