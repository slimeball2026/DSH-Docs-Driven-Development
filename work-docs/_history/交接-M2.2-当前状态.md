## 1. 本轮最重要的一件事：client 半侧启用成功

### 真因（一行代码）

`src/client/entry.tsx` 的 `wirePreview()` 里：

```js
const sidebarRight = ctx?.sidebarRight    // ← 就是这一行
```

**cordis 的 `ctx` 是 Proxy。读取一个没写进插件 `inject` 的服务时，它不返回 `undefined`，而是直接抛：**

```
Error: cannot get property "sidebarRight" without inject
```

`?.` 拦不住 —— 抛错发生在**属性读取那一刻**。

于是 `apply()` 在**第一条语句**就抛 → `registerPanel` 永远走不到 → 双注册不发生 → **面板不出现**。

### 为什么查了这么久（**值得记住**）

| 现象 | 会误导你去查什么 |
|---|---|
| `fiberPhase: active` | 以为加载失败 |
| factory 已注册（`duplicate factory registration`） | 以为 bundle 没下载 |
| `__DSH_BOOT__` 里有我们、batch 里有我们 | 以为宿主组合失败 |
| **crash 日志为空** | 以为 boot 没报错 |
| client `slots` 里没有我们 | 以为注册逻辑写错了 |

**全部指向错误方向。** 唯一能看到真因的地方是**浏览器控制台**，而它**不写 crash 日志**——因为 `@local/ddd` 不在前端的 required 集合（写死的 7 个官方包）里，只走 `warning` 分支。

> **教训：`fiberPhase: active` 只证明 entry 启动过，不证明 `apply()` 成功返回。**

### 修复

新增 `src/client/entry-logic.ts`（纯逻辑层，可被单测 import —— `.tsx` 无法被 Node 的类型剥离加载）。三处可选服务全部改走 `ctx.get(...)`：`sidebarRight` / `layout` / `sessions`。

## 7. 破了一条纪律（**已获用户授权，有记录**）

**「插件从不创建目录」** 被破了，因为 `ctx.fs` **没有 mkdir**，而一键初始化必须建 `docs/`。

用户的判断（我认同，且比原说法更准确）：
> 「那个被破的纪律初衷大概是适用于 ai 的，但你搞的功能本身是用户的 ui 操作，不会影响 ai 本身。」

原纪律的动机是**AI 的 IO 必须受沙箱约束**；而一键初始化是**用户点的按钮**，授权来源是用户的显式操作。

**边界**（`test/decoupling.test.js` 钉着）：
- 只允许 `server/mkdir-bridge.ts` 一个文件 import `node:`；
- 只允许 `node:fs/promises` + `node:path`；
- 必须有 `realpath` + `isInside` + 越界拒绝分支；
- 白名单文件若不再 import node:，测试会红（提示删白名单）。
