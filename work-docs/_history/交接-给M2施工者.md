## 0. 这个项目是什么（**先读这一节**）

> ⚠️ **这一节被漏过三次**（三个不同作者，其中一次还写「我不该重犯」）。
> 所以它现在**由系统强制**：索引块的 `【项目】` 行 + **H9** 判据。**我不是靠记得**。

### 0.1 一句话

> **让 AI 在动手改项目文档之前，必须先读过该读的文档；「读没读」由插件记账并强制，不是靠提示词嘱咐。**

这是一个 **DSH 插件**，名字叫「文档驱动开发」（DDD，Document Driven Development）。

> ⚠️ **DDD 在这里不是「领域驱动设计」**，是本插件名。这个缩写在本项目里**只有这一个意思**。

### 0.2 用户的原始设想

用户最初想要一个**可视化**工具：DSH 右栏三个分区（工作区树状图 / 交付成品网格 / 坟场），
配「阅读顺序」与「文档置信度」（绿/黄/红 + 原因）。

核心流程：**AI 不直接开工** → 问清需求 → 规划 → 产出文档 → **按文档施工** → 交接时更新阅读顺序与置信度。

> 最有价值的一句：「更建议写交接文档交给下一个会话」。
> 这不是功能，是**对「AI 会话是有限资源」的承认**。

**M2 就是把这个原始设想真正做出来的切片。** 前面三个切片都在为它铺路。

### 0.3 评审之后，项目变成了什么

架构评审（`文档驱动开发-架构评审与补充设计-v1.md`，**以它为准**）做了三处根本修正：

| 原设想 | 修正后 | 为什么 |
|---|---|---|
| 先做可视化 | **先做约束器**，M0/M1/M1.5 零 UI | UI 解决"看得见"，解决不了"AI 会不会照做"。后者才是价值 |
| 置信度写在散文里 | **frontmatter 元数据是真源**，图是渲染 | 手写散文索引必然漂移 |
| 插件做成 preset | **全局插件，按项目激活**（S1） | preset 会让标准模式看不到它，**且门禁能被"切个模式"绕过** |

## 1. 我的意图

**本项目**是「文档驱动开发」插件（DDD）——一个让 AI 在改文档前必须先读过文档的约束器。
**M2 的目标不是"加个 UI"，是"换一个技术栈"**，而且只换这一次。

M0/M1/M1.5 把约束器做完了：门禁会拦、交接能校验、健康度能自检。
但**人看不见它在干什么**——用户只能问 AI「我现在能改哪份文档？」，然后祈祷 AI 说的是对的。

**M2 要让这件事变成一眼可见**：必读进度、文档异常、待归档、交付成品，全部摆在右栏。

我的意图里有一条**比功能更重要**的东西：

> **M2 是第一次让"外部观察者"能看见这个插件的内部状态。**
> 所以 M2 的 UI 如果显示了**错的数据**，比没有 UI 更糟——
> 它会把"错误的信任"可视化。这正是 M2-Q1 要求先把 M1.5 三个条件修完的原因。

## 4. 坑（不要重犯）

| # | 坑 | 怎么避免 |
|---|---|---|
| 1 | **以为"UI 读了"等于"AI 读了"** | `readSet` 是**会话级**的。用户在看板点开必读文档，**门禁不会解锁**。这是设计（不变量说的是 **AI** 必须读过），README 要写清，否则会被当成 bug |
| 2 | **往索引块里塞 `generatedAt` / 百分比 / "当前阶段"** | 看板走 HTTP，索引块走 `context()`，**两条完全不同的通道**。塞进索引块＝重造 M0-5 的坑 |
| 3 | **在 client 里直接读写文件** | client 跑在浏览器里，**没有文件系统**。所有文件操作 POST 回 host |
| 4 | **只注册 `sidebar.panellist` 不注册 `main`** | 点入口行打不开页。`smoke` 必须有断言钉住**成对注册** |
| 5 | **改完 client 只看单测** | client bundle 有**两层缓存**（host 路由 + 浏览器）。必须 `build` + 重启 + **硬刷新**。**验收报告要写清"你刷了几次"** |
| 6 | **为了"看板更完整"自己编一个阶段推断器** | `【施工】` 行只有切片名（D5=B 拍板）。**「阶段」留空**，等有真源再填（SPEC R-4） |
| 7 | **上 TS 之后把 722 条测试改成 TS** | 测试仍跑 `.js`。SPEC §8.3 给了三条路，**必须选一条并证明"一条命令跑完 722+"** |
| 8 | **`server/` 里直接 `import node:fs`** | 走注入口。`decoupling.test.js` 要扩展到 `server/`（SPEC §5.3 第 3 条） |
| 9 | **归档时忘了保留原路径** | 还原要能放回原处。方案先定再动手（SPEC R-6） |
| 10 | **改完 `index.js` 的锚点不动验证** | M1.5 里我改坏过一次 `index.js`（`anchorsOf is not defined`，24 条红）。**在"刚验过的契约"上动刀，要重新走一遍验证** |

| 12 | **`git` 也会撞命名管道** | 同上 |
| 13 | **以为"单测全绿"就等于"改的东西在用"** | M1.5 栽过 3 次。M2 更容易栽（client 有缓存）。**廉价探针：面板显示只有新代码才有的版本号** |

## 8. 最后一句

**M0 证明了「AI 会先读文档」。M1 证明了「交接接得住」。M1.5 证明了「插件不会把项目弄坏」。**

**M2 要证明的是最后一件：人能不能自己看见它在干什么。**

**但 M2 有一个 M0–M1.5 都没有的风险**：前面的切片错了，AI 会撞墙（门禁拒绝、校验报错），
**错误是可见的**。而 UI 错了，**它会安静地显示错的数字**，用户会相信它。

> 所以：**M2 的每一条数据，都要能追到它的真源。**
> 追不到真源的，就留空——**留空比显示一个猜的数字好**。
> 这条和 §3.0 的三个条件、和 SPEC R-4 是同一个道理。
