## 1. 三步核对（每步都要留证据）

### 第 ① 步：在一个**会话**里读一份文档 → 条上出现 `✓`

1. 打开一个 **cwd 在 DDD 工作区**的会话（例如 `DDD全流程测试`）。
2. 打开右侧栏的「文档驱动开发」页签。
3. 让我（那个会话里的 AI）读一份必读文档，例如：

   ```
   读一下 docs/spec-report.md
   ```

4. **看页签底部的「AI 阅读顺序」条**：那一份 chip 上应该出现 **`✓`**，
   进度从 `0/3` 变成 `1/3`。

**期望**：`✓` 出现（不是绿点 —— 绿色专属于置信度）。

**贴回来的证据**：条上的进度数字（例如 `1/3`），以及该 chip 的样子（`✓` / 空心圆）。

---

### 第 ② 步：`edit` 改它 → API 的 `read` 变回 `false`

1. 让同一个会话里的 AI 改那份文档（改正文即可）。
2. 在**那个会话**里跑这条命令（把 `<会话 id>` 换成该会话的 id）：

```powershell
$w = "C:\Users\slimeball\Documents\deepseek-harness\DDD全流程测试"
$u = "http://127.0.0.1:52731/api/ddd/index?cwd=" + [uri]::EscapeDataString($w) + "&sessionId=<会话 id>"
$j = (Invoke-WebRequest -Uri $u -UseBasicParsing).Content | ConvertFrom-Json
"gate = $($j.gate.read)/$($j.gate.required)"
$j.required | ForEach-Object { $_.id + "  read=" + $_.read }
```

**期望**：

| 项 | 期望值 |
|---|---|
| 被改的那份 | `read=False` ← **这是门禁实时的证据** |
| 没被改的其它份 | `read=True`（如果第 ① 步读过） |
| `gate` | 分母不变，分子**减 1** |

> ⚠️ **必须带 `sessionId`**。不带的话 `readSet` 会退回共享集合（单会话脚本用），
> 读数不代表你的会话。这条在 `index.js` 的 `locate()` 里写着。

**贴回来的证据**：上面那条命令的完整输出。

---

### 第 ③ 步：**刷新面板** → `✓` 仍然在（**这条是关键**）

1. 刷新页面（或切走再切回，让右栏重建）。
2. 重新打开那个会话的 DDD 页签。
3. **看那一份 chip**。

**期望**：

| 通道 | 第 ② 步之后 | 第 ③ 步之后 | 为什么 |
|---|---|---|---|
| **API `gate.read`** | `false`（实时） | 仍然是 `false` | 门禁必须实时：改了就要重读 |
| **条上的 `✓`** | **仍然在** | **仍然在** | 「接手时读过」这个事实没变 |

**如果 ③ 的 `✓` 消失了** → 说明 `rememberReadOf` 或 `localStorage` 有问题，请把下面这条命令的输出贴给我：

```powershell
# 在浏览器 F12 Console 里跑（看这个会话的记忆键里存了什么）
Object.keys(localStorage)
  .filter(k => k.startsWith('ddd.readOrder'))
  .forEach(k => console.log(k, '=>', localStorage.getItem(k)))
```

期望看到形如：

```
ddd.readOrder.everRead.<会话 id>  =>  spec-report
ddd.readOrder.collapsed           =>  0
```

> ⚠️ **注意键里带的是会话 id**，不是全局的 `ddd.readOrder.everRead`。
> 如果看到**没有后缀**的那个键，说明记忆退化成全局了 —— 那是用户之前抓到的泄漏。
