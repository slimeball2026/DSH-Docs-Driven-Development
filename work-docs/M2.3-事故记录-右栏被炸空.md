# M2.3 事故记录：会话右栏被整个炸空

> **日期**：2026-11-14 ｜ **发现人**：用户（实机点击）｜ **定位与修复**：M2.3 施工者
> **严重度**：**高** —— 不是"我的页签不显示"，而是**整个右栏变空，且切会话也回不来**

---

## 1. 症状（用户原话）

> 「我在已经开始工作的一个会话里点开文档驱动开发的右侧栏，能正常显示，
> 但如果我去『DDDUI测试』里还没发任何话的情况下开右栏，右边直接纯空页，
> 再切回原来能正常显示的会话，它也变空了。」

拆成三条，第三条是**决定性的**：

| # | 现象 |
|---|---|
| 1 | 有历史的会话里点开页签 → **正常** |
| 2 | 切到**还没发过话**的新会话 → 右栏**纯空页** |
| 3 | **切回原来那个正常的会话 → 它也变空了** |

> **为什么第 3 条是决定性的**：
> 取数失败只会让**这一格**显示"没有数据"，不可能让**已经渲染好的另一格**变空。
> 能让整棵子树消失的只有一件事：**React 在渲染期抛错 → 错误边界卸载整棵树**。
> 这一条把排查方向从"数据/接口"直接扭到"渲染"。

---

## 2. 真因（一行）

`src/client/session-tab.tsx` 第一版：

```js
export function SessionTab({ sessionId = '', useSessions, wiring }) {
  // ⚠️ useSessions 是**框架注入的 hook**，而这里在 useMemo 的回调里调它
  const cwd = React.useMemo(
    () => (wiring === undefined ? '' : wiring.cwdOf(useSessions, sessionId)),
    [wiring, useSessions, sessionId],
  )
  ...
}
```

**`useSessions` 是 `SnapshotSelectorHook`（React hook）。**
`useMemo` 的回调**在渲染期执行**，于是这个 hook 被"有条件地"调用：

- 有 cwd 的会话 → 走了 `cwdOf` 内部的不同分支；
- 新会话（cwd 为空）→ 走另一条路径。

hook 调用序列因此变化 → React 抛：

```
Rendered more hooks than during the previous render.
```

→ 错误边界（宿主那层的）卸载**整棵右栏子树** → 第 2、3 条症状。

### 2.1 为什么活体 Slot 检查提前给出了线索

用 `cordis_inspect_query` 的 client `Slots.listSubTree` 对比两个席位：

| 席位 | `@local/ddd` 的 `active` |
|---|---|
| `main`（主栏整页，工作正常） | **`true`** |
| `sidebar.right.pane.tab`（右栏页签，坏的） | **`false`** ← |

其他所有插件的 occupant 都是 `true`。**只有我们这一格是 `false`** ——
这说明"注册发生了，但这一格没能正常渲染"，而不是"没注册"。
这条证据直接把范围缩到**组件本身**，而不是注册链路。

## 3. 顺带修掉的三处（都会独立造成问题）

### 3.1 循环依赖：`session-tab.tsx` ↔ `index.tsx`

第一版 `session-tab.tsx` 直接 `import { createController } from './index.tsx'`，
而 `index.tsx` 要 `import { SessionTab } from './session-tab.tsx'` —— **互引**。

单文件 CJS 打包下函数声明会提升、通常"碰巧能跑"，但那属于运气。
**改法**：`controller` 的造法通过 `wiring.makeController` 注入，组件不 import `index.tsx`。

### 3.2 `MainPage` 与 `Dashboard` 并列渲染

两者都带 `height: 100%`，在窄栏里互相挤压。
**改法**：只渲染 `MainPage`（它已含图谱/交付/归档三个 tab），门禁进度由底部 `ReadOrderBar` 承担。

### 3.3 `inject` 回传 `sessionId` 覆盖框架的 standard prop

第一版：

```js
inject: (sessionId) => ({ wiring, sessionId: typeof sessionId === 'string' ? sessionId : '' })
```

`sessionId` 本来就是框架注入的 **standard prop**。在 `inject` 里回传同名键，
可能覆盖框架给的那个值（`active: false` 的嫌疑之一）。
**改法**：`inject: () => ({ wiring })` —— 官方两个实现（`documentpreview` / `files`）
的 `inject` 都**只回传 face**，不回传 sessionId。

### 3.4 补上**页签级错误边界**（最重要的一条防线）

即使将来又写错，也只能坏**这一格**，不许连累整个右栏。

这符合本项目更根本的纪律：**插件故障不能变成宿主故障**
（`adapters/guard.js`、`server/routes.ts` 的 `registerRoutes` 都写着这一条）。

实现：`TabErrorBoundary`（class 组件 + `getDerivedStateFromError` + `componentDidCatch`），
把 `SessionTabInner` 包起来。抛错时显示「这个页签出错了」+ 原始错误文本，
**其余右栏不受影响**。

## 5. 教训（**给下一个写 DSH client 插件的人**）

| # | 教训 |
|---|---|
| 1 | **框架注入的 standard props 里，凡是 `useXxx` 都是 hook**，只能在组件顶层无条件调用。放进 `useMemo` / `useCallback` / `if` / `&&` 里都会炸 |
| 2 | **"整个面板变空" ≠ 数据问题**。判断口诀：**如果另一格也空了，就是渲染期抛错**，去查 hook 与 render 逻辑，别查接口 |
| 3 | **活体 Slot 的 `active` 字段比日志有用**。同一席位里"只有我是 false"直接指向组件本身 |
| 4 | **插件必须自带错误边界**。"我的页签坏了"和"整个右栏坏了"是两个严重度完全不同的故障 |
| 5 | **宁可纯读快照，不要为了"更正统"去调 hook**。`getSnapshot()` 没有 hook 顺序问题；订阅可以另找地方做 |
| 6 | **组件之间互引要警惕**。`A import B` + `B import A` 在单文件打包下"碰巧能跑"，出事时极难查 —— 用参数注入打断环 |
| 7 | **测试桩也要如实反映依赖**。产物级验证的 react 桩漏了 `Component`，一加载就 `Class extends value undefined` —— 那是桩的缺陷，但它顺带证明了这条链路对 `React.Component` 是硬依赖 |
