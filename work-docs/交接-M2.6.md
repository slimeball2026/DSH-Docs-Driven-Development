## 0. 这个项目究竟是什么（**先读这一节，它是本文最重要的一段**）

> 这一节被漏过三次（三个不同作者），所以强制保留。

### 0.1 一句话

> **让 AI 在动手改项目文档之前，必须先读过该读的文档；「读没读」由插件记账并强制，不是靠提示词嘱咐。**

这是一个 **DSH 全局插件**，名字叫「文档驱动开发」（DDD，**不是**领域驱动设计）。

### 0.2 用户的原始设想（**为什么会有这个项目**）

原始文档在 `C:\Users\slimeball\Downloads\文档驱动开发架构设想.md`（25 行）。**你必须读它**，因为它是这个项目存在的理由。核心三句：

> 定位：一个 dsh 的可视化文档驱动开发协助工具……位于 dsh 右侧窗口栏中
> 优势：文档本身不植入 ai 上下文，任意更改也不会破坏缓存前缀，且**易于跨会话转接工作**
> 粗略流程：用户使用插件时，**agent 不会直接开工**，而是先询问用户获取更多信息，做工程规划，
> 然后产出这些文件：树状图样式文档（阅读顺序文档）、总体规划路线图（也许是 spec）、
> 工程记录文档等，随后才按照这些文档进行开发（**更建议写交接文档交给下一个会话**）

设想里最有价值的一句话是「**更建议写交接文档交给下一个会话**」。
**这不是功能，是「AI 会话是有限资源」的承认。** 理解这一点，才理解为什么整个项目围绕「交接」而不是「更聪明的 AI」。

### 0.3 评审之后，项目变成了什么

架构评审（`文档驱动开发-架构评审与补充设计-v1.md`，1359 行）做了**三处根本修正**：

| 原设想 | 修正后 | 为什么 |
|---|---|---|
| 先做可视化 | **先做约束器**，M0/M1/M1.5 零 UI | UI 解决"看得见"，解决不了"AI 会不会照做"。后者才是价值（Q1 = B） |
| 置信度写在散文里 | **frontmatter 元数据是真源**，图是渲染 | 手写散文索引必然漂移（评审 §2.2 用用户的 00 索引实证过） |
| 插件做成 preset | **全局插件，按项目激活**（S1） | preset 会让标准模式看不到它，**且门禁能被"切个模式"绕过** |

### 0.4 它具体怎么工作（四个环节）

| # | 环节 | 落点 | 一句话 |
|---|---|---|---|
| 1 | 激活判定 | `adapters/probe.js` | 探不到 `AGENTS.md` 的 `<!-- ddd:index` 或 `docs/` 合法 frontmatter → **整个插件对该项目 no-op**，绝不误伤普通仓库 |
| 2 | 扫描建注册表 | `docs/scan.js` + `adapters/registry.js` | 把 `docs/**.md` 读成条目（meta / 指纹 / 有无 error）。**坟场永不进索引** |
| 3 | 索引注入 | `adapters/inject.js`（`systemPrompt.context()`） | 每轮往模型上下文塞 `【门禁】/【预算】/【项目】/【已读】/【未读】/【禁止执行】/【文档异常】` |
| 4 | **门禁** | `adapters/guard.js`（`ctx.tools.guard()`） | 模型调 `write`/`edit` 打 `docs/` 时**按路径判**：要改的那份读过没？**没读过就拒绝** |

**关键在 3 与 4 的分工**：3 只是"让人看见清单"，**4 才是那个 `if`**。
只有 3 就是提示词嘱咐（教练模式已证明会失效），只有 4 就是莫名其妙被拒。

### 0.5 三条铁律（破坏了项目就失去意义）

| # | 铁律 | 破坏了会怎样 |
|---|---|---|
| 1 | **门禁必须是代码里的 `if`**，不是提示词嘱咐 | 退化成软约束（教练模式已证明会失效） |
| 2 | **全局挂载，项目级生效**（S1，不做 preset） | preset = 标准模式看不到 + 门禁能被切模式绕过 |
| 3 | **Q1–Q13 / R1–R5 / S1 / S2 / M1-Q / P / M2-Q 已冻结** | 改冻结决策必须有用户授权记录 |

### 0.6 术语

| 词 | 含义 |
|---|---|
| **DDD** | 本插件名。**不是**领域驱动设计 |
| **受管文档** | `docs/` 下带合法 frontmatter 的 `.md` |
| **unmanaged** | `docs/` 下完全没有 frontmatter 的 md。不进索引、不报异常，但可写 |
| **激活标记** | T1: 合法 frontmatter；T2: `AGENTS.md` 含 `<!-- ddd:index`。**没有标记 → 插件 no-op** |
| **坟场** | `docs/_graveyard/`，只读、不进索引、平铺 |
| **M0-5 红线** | 索引块**不得含快变量**（时间戳 / 轮次 / 百分比）。内容一变宿主就 append 一条新历史消息 |
| **双注册** | Q7 = C：`sidebar.panellist`（左栏入口行）+ `main`（主栏整页）。**少一个就白做** |
| **root scope / session scope** | 主栏席位无会话（拿不到 cwd、预览必抛）；右栏页签有会话（自动有 cwd、能预览） |
| **readSet** | 「本会话读过什么」——host 侧 `WeakMap`，**内存态**，宿主重启归零 |
| **勾（✓）** | 阅读顺序条上的已读标记。**只增不减、按会话隔离**，与门禁实时读数分离 |

## 5. 四条必须知道的坑（**按代价排序，全部本轮实测**）

### 5.1 【最贵】改 host 侧代码**必须重启宿主**，没有热更新

我在这一点上**判断错过一次并误导了用户**。准确规则：

| 改了什么 | 怎么生效 |
|---|---|
| `ddd-bundle/lib/client.js`（client 侧构建产物） | 重建 + **刷新页面** |
| **host 侧任何 `.js` / `.ts`（`index.js`、`tools/*`、`core/*`、`adapters/*`）** | **必须重启宿主** |

**没有打包 = 进程启动时加载文件 = 之后改的源码不会被读到。**

我自己踩的实例：
- 18:48 改 F1/F3 → 18:49 用户重启 → **生效** ✅
- **19:07 改 `when.js` → 用户以为是同一个进程 → 测出来还是旧文案** ❌

⇒ **每次改 host 侧代码后，主动提醒用户「要重启才生效」。** 别让他白测一轮。

### 5.2 【重要】`no-project-root` 不是「拿不到目录」，是「这个目录不是 DDD 工作区」

**我在这里修错了两次**，记录如下以免你重犯：

| 轮次 | 我以为是 | 做了什么 | 结果 |
|---|---|---|---|
| 1 | 没现探缓存 | 加 `ensureProbe` | ❌ 无效 |
| 2 | 没 await 异步判定 | 四处补 `await` | ❌ 无效（但这两处本身是对的，保留） |
| 3 | **归因错了** | 只改文案 | ✅ 但**仍未实机验** |

**真机制**（已核实）：`adapters/probe.js` 的 `detect()` 第 3 步

```js
// ---- 3. 探不到 → 静默降级（规则 3）
return { hasMarker: false }        // ← 按设计就没有 projectRoot
```

⇒ `core/scope.js` 的 `hasProjectRoot === false` **永远先命中**，`NO_MARKER` 分支几乎走不到。
实测：`ensure(空目录) => {"hasMarker": false}`（确实没有 `projectRoot`）。

**用户 2026-11-14 拍板：只改文字，不改机制。** 理由：改 `detect()` 会破坏「探不到就 no-op」铁律；收益只是"一句话更准确"。

⇒ **不要再试图修这个机制。** 真正的使用说明由 M2.6 写进 README 承担。

### 5.3 变异存活时，**先查"测试跑到了没"，再查"断言够不够"**

本项目栽过三次。本轮又栽两次：

| 变异 | 存活原因 |
|---|---|
| `bar-persists-without-guard` | `.tsx` 进不了 Node 单测 → **纯逻辑对 ≠ 组件用了它** |
| `gate-never-ensures-probe` / `tool-drops-await-assert` | 测试只覆盖 `when.js` 单元层，没覆盖 `index.js` 接线与工具里的 `await` |

**排查顺序固定**：先确认覆盖（跑到的文件对不对）→ 再确认断言（是不是恒真）→ 最后怀疑变异本身写错。

### 8.1 一条关于"证据等级"的方法

M2.5 的交接给每条结论都标了**证据等级**（机器 / 人眼 / 推断）。原因：

> 我（M2.5）**读不了图**（模型不支持图像输入）。用户给的 5 张截图我一个字都没看到。
> 所以 W1/W2 的结论只能记成"用户口述没问题"，而不是"我验过"。

⇒ **M2.6 也一样：标清谁能证明什么，比多写一句"已验"有用。**
这个项目已经栽过三次「把上一轮的结论当成这一轮的事实」。
