# 无 UI 版全流程演练 · 执行提示词

> **用途**：在 M2（UI）开工**之前**，用**当前无 UI 的版本**跑一次完整的 DDD 全流程，
> 验证「立项 → 按文档施工 → 中途改文档 → 交接 → 新会话接续」这条链路**没有 UI 也走得通**。
>
> **写它的原因**：M0/M1/M1.5 验的都是**单点判据**（门禁会不会拦、交接能不能校验）。
> **从来没有人从头到尾跑过一次"一个项目从零到交接"**。M2 会新增 UI，
> 如果那时才发现主流程有断点，会分不清是 UI 引入的还是本来就有。

---

## 0. 结论先说：**可行，但有 4 个必须照做的前提**

| # | 前提 | 为什么 |
|---|---|---|
| **1** | **工作区必须是一个全新的空目录** | 不能在 `DDD插件施工` 里面（根目录不是 DDD 项目，且会撞上 `_m15-live2` 等夹具） |
| **2** | **第一个动作必须是手写 `AGENTS.md`**（含 `<!-- ddd:index -->`） | **没有激活标记 → 插件整个 no-op → 4 个 `doc_` 工具根本不会出现**。<br>此时 `write` 工具是放行的（`guard.js:92` `if (!activated) return undefined`），所以**这一步一定成功** |
| **3** | **建完标记后要等 2 秒以上，或先做一次无关操作** | `probe` 有 2 秒 TTL（`adapters/probe.js:24`），标记不是立刻生效 |
| **4** | **第 2 个会话必须是"全新会话"，不是续话** | 交接的意义就是"另一个会话接得上"。同一个会话看不出交接有没有用 |

**其余都可行**，因为：
- `doc_new` 支持 `role: index`（`docs/schema.js` 的 `ROLES` 第一项就是 `index`）；
- 门禁、交接校验、`doc_health` 都是 host 侧功能，**不依赖 UI**；
- M1.5 已把「无 frontmatter 可写」「坏元数据可修」这些死锁解开了。
