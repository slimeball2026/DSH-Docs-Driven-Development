## 2. 我上一轮引入的新缺陷（最重要）

### 2.1 现场

```
seq 70   edit read-order        ✅  模型手写清单：1. read-order / 2. spec-1 / 3. instruction-1
seq 76   doc_health             ✅  5 项全过
seq 81   doc_new handover-1     ✅  工具自动把交接插成第 1 条 → 清单变 4 条
seq 87   read read-order        ✅  模型发现「3 条」不对
seq 93   edit read-order        ✅  改成 4 条
```

**模型的原始顺序完全正确**（先定稿索引 → 体检 → 再写交接），
它照做了手册的每一步。**是工具改的。**

### 2.2 AI 自己的措辞（值得逐字读）

> 这不是「把没做的事写成做了」，那种错还能自查；
> 这是**你核对过的状态在核对之后被工具改掉了**，
> 而手册的顺序规则里没有这一步的位置。

> 真正的教训：**顺序不是线性的，有一条边是从「建交接」指回「索引」的**。

### 2.3 根因

上一轮我加 `registerHandoverInIndexFile` 时，回执写的是：

> ✅ 入口索引的必读清单已自动登记本份交接（**不用你再改 `read-order` 加自己**）。

**这句字面是真的，但它只说了"你不用加自己"，没说"你手写的那份清单其余部分现在过期了"。**

### 2.4 修法

工具既然改了别人的文件，就有义务**说清改成了什么**：

- `registerHandoverInIndex` 回传 `countBefore` / `countAfter`；
- `doc_new` 的 schema 声明 `indexCountBefore` / `indexCountAfter`（**必须声明**，
  宿主 `additionalProperties: false`）；
- 渲染时明确写：「必读清单从 3 条变成了 4 条」「你写过的计数现在过期了」
  「改它要整份重读，所以**宁可写状态、别写计数**」。

## 6. 一句话

> **改善是真的：失败归零、字符减半、交接轮步数减半。**
> **但这一轮最重要的发现不是"改好了"，是"我的修复本身产生了新的假话"** ——
> 工具改了一个模型已经核对过的文件，而没告诉它。
>
> 这个模式值得记住：**任何"帮你省一步"的自动改动，都必须说清它改了什么。**
> 否则省下的那一步，会用一句假话的形式还回来。
