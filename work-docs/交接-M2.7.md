## 0. 这个项目究竟是什么（**先读这一节**）

> 这一节被漏过三次（三个不同作者），所以强制保留。

### 0.1 一句话

> **让 AI 在动手改项目文档之前，必须先读过该读的文档；「读没读」由插件记账并强制，不是靠提示词嘱咐。**

这是一个 **DSH 全局插件**，名字叫「文档驱动开发」（DDD，**不是**领域驱动设计）。
它被 profile 用 junction 链接（`@local/ddd` → 本仓库 `ddd-bundle/`）。

### 0.2 四个环节

| # | 环节 | 落点 | 一句话 |
|---|---|---|---|
| 1 | 激活判定 | `adapters/probe.js` | 探不到标记 → **整个插件对该项目 no-op** |
| 2 | 扫描建注册表 | `docs/scan.js` + `adapters/registry.js` | 坟场永不进索引；readSet 是 `WeakMap` 内存态 |
| 3 | 索引注入 | `adapters/inject.js`（`systemPrompt.context()`） | 每轮塞 `【门禁】/【预算】/【怎么做】/【已读】/【未读】` |
| 4 | **门禁** | `adapters/guard.js`（`ctx.tools.guard()`） | 模型写 `docs/` 时按路径判，**没读过就拒** |

**关键在 3 与 4 的分工**：3 只是"让人看见清单"，**4 才是那个 `if`**。

### 0.3 三条铁律（破坏了项目就失去意义）

1. **门禁必须是代码里的 `if`**，不是提示词嘱咐；
2. **全局挂载，项目级生效**（S1，不做 preset）；
3. **Q1–Q13 / R1–R5 / S1 / S2 / M1-Q / P / M2-Q 已冻结** —— 改冻结决策必须有用户授权记录。

### 0.4 术语

| 词 | 含义 |
|---|---|
| **标绿** | `doc_mark(id, status: 'authoritative')` —— `authoritative` 在 UI 里显示成 🟢✅ |
| **坟场** | `docs/_graveyard/`，只读、不进索引 |
| **M0-5 红线** | 索引块不得含快变量（时间戳/轮次/百分比） |
| **pinned** | 索引块里永不裁剪的段（门禁/项目/施工/预算/怎么做） |
| **标绿快照** | `_artifacts/ddd-mark-snapshots.json`，M2.6 新增，见 §3.3 |

## 3. M2.6 到底改了什么（按机制分组）

### 3.1 交接的写权限：从"一律禁止"到"完全放开"

**演进三阶段**（这条线走了三次，每次都是实测打回）：

| 阶段 | 策略 | 为什么被打回 |
|---|---|---|
| 原始 | `write/edit` 全拒 | 与 **SPEC-M1 §4.4** 不符（原文允许 `edit` 已有 draft） |
| 第一次 | 只放开 `draft` | `session-47f59223`：AI 标绿后才发现哈希过时 → **33 000 字往返思考** |
| **现在** | **任意状态都可 `edit`**，`write` 仍拒 | 用户拍板 |

**安全性依据**（用户要求核实）：`git log -- 交接-M2.6.md` 显示 **M2.6 一次都没改过自己的交接**
——真实使用中交接是"照做"的对象，不是"改"的对象。

落点：`core/roles.js` 的 `ROLE_WRITE_POLICY.handover = { write: DENY, edit: ALLOW }`。

### 3.2 交接校验：H4 从 error 降为 warn

**理由**：H4 逼的是"人话迁就正则"。实测一份**人话写得很实在**的交接被判 2/2 全挂：

```
- 两份文档正文严格为 1 和 2：我用 PowerShell 逐份比对，两行都输出 OK
```

它确实验过了，只是不会写成 `3/3 通过` 那种形状。AI 自述：
> 「**我手里有证据，但我不知道判据在找什么形状**……这一步的成本没法靠"更认真地验"降下来，只能靠"读过一遍报错"。」

落点：`core/handover.js` 里 `const h4Level = 'warn'`（H1–H3 仍是 error）。

**同时做的两件事**：
- 判据接受「命中」（`3/3 命中` 与 `3/3 通过` 语义相同，只认后者是偶然）；
- 报错**列出全部**不合格条目 + 说清「为什么不算」+ 给出改法。

### 3.3 标绿快照对账（新机制，H-6）

**要解决的问题**（用户原话）：
> 「**不该预设 AI 能预料到自己真的没东西要改。**」

**机制**：
1. `doc_mark` 标 `authoritative` 时，把**其它文档此刻的指纹**写进 `_artifacts/ddd-mark-snapshots.json`；
2. `doc_health` 读回来对账，发现某份被引用的文档指纹变了 → 报 **H-6 warn**。

**三条纪律**（都在 `tools/doc-mark.js` 与 `core/markSnapshot.js` 的注释里）：
- 只对 `authoritative` 做；
- **完全静默失败**（快照写不进去绝不能让标绿失败）；
- 只报 warn，不阻断。

**对账语义**：变了才报；没变不报；文档被删/归档（拿不到指纹）**不报**（引用悬空由 V5 管）。

### 3.4 索引块新增【怎么做】行

`core/render.js` 的 `TAG.howto`，`pinned: true`：

```
【怎么做】归档→doc_mark 标 void；交付→放 deliverables/；阅读顺序→改各文档 order 且改入口索引正文。别读插件源码。
```

**为什么**：实测 13 个回合里 3 个（共 25 次工具调用）在翻插件源码 —— 因为注入块从没说过
「归档/交付/改阅读顺序」各等于什么操作。

⚠️ **这一行受 pinned 预算硬约束**：`renderM1.test.js` 有一条「pinned 总长 ≤ 180」的判据。
加内容前先看它。

### 3.5 两处 UI

- **交付页点不开**：`DeliverableCell` 原来写死 `cursor: pointer` + `onOpen?.()`，
  而主栏（root 面板）**没有会话上下文**，`openResource` 必抛 →
  改成「不可点 + 明说去会话页右侧栏」。
- **右栏页签没接线**：`MainPage` 有**两个**调用点（主栏 `index.tsx` + 页签 `session-tab.tsx`），
  M2.6 第一版只修了主栏。页签是 **session scope，能开预览** —— 已补 `onOpenFile`。

### 3.6 仓库整理

- 14 份旧交接 → `_history/`；10 份报告 → `_reports/`；`_review/` → `_history/_review/`（相对引用已改写并逐字比对）

## 4. 坑（**按代价排序，全部本轮实测**）

### 4.1 【最贵】改 host 侧代码**必须重启宿主**，没有热更新

| 改了什么 | 怎么生效 |
|---|---|
| `ddd-bundle/lib/client.js`（client 产物） | 重建 + **刷新页面** |
| **host 侧任何 `.js`（`index.js`、`tools/*`、`core/*`、`adapters/*`）** | **必须重启宿主** |

**没有打包 = 进程启动时加载文件**。每次改完主动提醒用户重启，别让他白测一轮。

### 4.2 【重要】工具的**返回值形状**是宿主侧契约，单测看不见

`tools/define-tool.js` 编译出的 output schema 是 `additionalProperties: false`。
**返回值里多一个键，整个工具调用就失败**。

实例（`session-f36fd404`）：
```
Error: tool "doc_mark" returned invalid output:
"value.snapshotRefs" is not a declared property (additionalProperties: false)
```
后果：**每次标绿都失败** → AI 反复重来 → turn 3 输出 25 038 字符（上一轮 8 657）。

⚠️ **单测直接调 `tool.execute()`，宿主的 output 校验不在那里**，所以单测全绿也照样炸。
⇒ 应对：断言**实际返回对象的键集合**（`test/n2-params.test.js` 有一条）。

**同类风险点**：`input` schema（同样 `additionalProperties: false`）、`output.render` 的存在性（注册期才验）。

### 4.3 【重要】反向断言会被「劝阻句」自己命中（**踩过三次**）

1. M2.5「不许让人确认工作目录」—— 劝阻句"不要确认工作目录"被匹配
2. M2.6「不许自己写 AGENTS.md」—— 同理
3. M2.6「页签不许出现 `previewDisabled`」—— **注释里写"故意不写它"也算出现**

⇒ 解法：先剔除含「不要/别/不许/禁止」的行，再断言剩下的内容里没有 X
（`test/tools.test.js` 的 `instructionsOf()`）。或者**注释里根本不写出那个字面量**。

### 4.4 【重要】改文案会**静默废掉变异锚点**（踩过六次）

每条变异是一个 `from`/`to` 字面替换。改了源码里那段字，锚点就匹配不到，
而 `verify-anchors.mjs` 会报「锚点出现 0 次，CAUGHT 是假的」。

⇒ **每次改文案后先跑 `node _m23\verify-anchors.mjs`**（0.2 秒）。

### 4.5 变异存活时，**先查"变异真的施加了吗"，再查"断言够不够"**

本轮又栽两次：
- 换行符写成 `\r\n`（文件是 LF）→ 只删掉注释行、prop 还在 → 存活
- 把 `h4Level = 'warn'` 改成 `'ok'` → `push` 对非 `'error'` 一律进 warnings → **行为没变**

**排查顺序固定**：查变异是否真的施加 → 查覆盖（跑到的文件对不对）→ 查断言（是不是恒真）。

### 4.6 交接文档里的数字是**上一轮的快照**

M2.6 接手时 `交接-M2.5.md` 写「阅读顺序变异 8/8」，实跑是 5/8 + 3 个 BAD-ANCHOR。

⇒ **接手第一件事：把 §2.3 全重跑一遍**。

### 4.7 已知但**未修**的真 bug：**分段读记录陈旧指纹**

`adapters/observe.js` 的 `textFromReadResult()` 只在读到文件末尾（有 `(End of file - total N lines)`）
时才还原正文；分段读（`read(offset, limit)`）返回 `undefined`。

而 `adapters/registry.js` 的 `markRead()` 在 `freshText === undefined` 时：
```js
readSetFor(session).set(id, { fingerprint: entry.fingerprint, ... })  // ← 用的是注册表缓存值
```

**后果**：注册表缓存若已过期，记下的是**旧指纹**，门禁随后报「你读过的是旧版」——
用户看起来像"刚读过却说没读"。

实测（`session-f36fd404`）：
```
167 read  offset=50 limit=30
172 edit  → Error: 你读过的是 v9434e6，磁盘已是 v8afd92
180 read  （完整）
185 edit  → 成功
```

**候选修法**（未实施，需用户拍板）：
1. 分段读**只记「读过」不记指纹**（最保守，但门禁拿不到指纹就无法判"改之前是否读过同一版"）
2. 分段读时**不覆盖**已有指纹（若已完整读过）
3. 分段读时**现读盘算指纹**（违背「同步记账不读盘」的设计）
4. 干脆**不把分段读算作读过**（最诚实，但会让 AI 白读一次）

⚠️ 选哪个都影响门禁语义，**别自己拍**。

## 附：会话日志怎么读（M2.7 一定会用到）

```powershell
# 1. 找会话（id 在目录名里，不在文件名里！）
Get-ChildItem "$env:DSH_HOME\sessions" -Recurse -Directory | Where-Object { $_.Name -like '*<前8位>*' }

# 2. 解码（多 frame zstd，不能直接 zstdDecompress）
node _m23\decode-session.mjs <session.v4.jsonl.zstd> _m26\s.jsonl

# 3. 导出成可读文本
node _m26\dump-session.mjs _m26\s.jsonl 700 > _m26\s.txt
```

⚠️ 记录形状的两个坑（我踩过）：
- `tool/call` 用的是 `data.name` / `data.arguments`（**不是** `toolName` / `input`）
- `tool/result` 的正文在 `data.message.content[0].text`，**且 seq 比对应调用大 1**
- `user/message` 的 `content` 是 `[{type:'text',text}]`，直接 `String()` 会得到 `[object Object]`
