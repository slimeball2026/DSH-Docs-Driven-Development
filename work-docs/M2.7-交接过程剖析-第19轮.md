## 3. ★ 我的修法 2 让事情变糟了（这一节是自我审计）

### 3.1 数据

`20cf9da` 的语义是「窗口读**不更新**已读指纹」。于是：

| 情形 | 之后写操作的成功率 |
|---|---|
| **完整读** → 写 | 8 次里成功 **7** 次 |
| **窗口读** → 写 | 5 次里成功 **0** 次 |

逐条现场：

```
seq 124 窗口读 → seq 129 edit      ❌ 被拒
seq 149 窗口读 → seq 154 doc_mark  ❌ 被拒  ← 第一次标绿失败
seq 187 窗口读 → seq 192 edit      ❌ 被拒
seq 239 窗口读 → seq 244 edit      ❌ 被拒
seq 261 窗口读 → seq 266 edit      ❌ 被拒
```

### 3.2 因果链

```
seq 144 edit 成功
  → seq 149 read(limit=10)      ← 模型想省 token，只看 10 行
  → seq 154 doc_mark 被拒       ← 修法 2：窗口读不更新指纹
  → seq 159 read（完整）
  → seq 164 doc_mark 成功
```

**在修法 2 之前**，seq 154 那次 `doc_mark` 会**成功** ——
因为窗口读会把注册表里的当前指纹写进 readSet。

⇒ 我为了堵一个**本轮没有发生**的缺陷（外部改动后只读片段就能拿到放行），
付出了**每条窗口读必撞一次墙**的代价。

### 3.3 我判断错在哪

修法 2 的收益是"防误放行"——但那是**前提条件**：
「文件被**别人**改过，模型只读了片段」。

本轮 6 次窗口读里，**没有一次**是这个场景。全是：
- 刚自己改完，想省 token 只看 10~12 行，好确认格式；
- `doc_mark` 前想知道 frontmatter 长什么样。

而这些恰恰是**「改完即变未读」这条设计本身**逼出来的行为。

> **我那笔修复的方向没错，但它把成本加在了最高频的路径上，
> 而收益落在一个本轮从未出现的场景。**

## 4. AI 自述的「最难」 vs 日志里的实际

AI 说最难的是**「读—改—失效」循环**与**「证据不能过时」互相冲突**。
逐条核对：

| AI 说的 | 日志核验 | 判定 |
|---|---|---|
| `handover-1` 至少 read 5 次 | **实际 12 次** | 它低估了 |
| `read-order` 约 3 次 | **实际 4 次（含 1 次窗口读）** | 基本准 |
| §5 被判「4/4 无形式」并改写 | ✅ seq 89 报出、修正后 seq 114 通过 | 准 |
| `old_string` 撞了 3 次 | ✅ seq 139 `matched 3 times` | 准 |
| 标绿后改 read-order 导致 §2 过时，H-6 抓到 | ✅ H-6 报出 3 次 | 准 |
| **「先说假话」的诱惑：先写引用再建文档** | ⚠️ **日志不支持**：seq 84 `doc_new` 先建，seq 94 才 edit | **它记错了** |

**最后一条很重要**：AI 主动"认领"了一个**它没犯的错**。
它不是撒谎，是**把"这类活容易犯的错"和"我做过的事"混了**。
⇒ 模型的自我报告**既可能低估**（12 次说成 5 次）**也可能虚构**（认领没做过的错）。
这印证了交接 §8 第 5 条：「模型的自我报告不是事实」。

## 5. 交接过程里三个**没被修的机制问题**

### 5.1 `doc_new` 建完就该算"已读"，但 `doc_mark` 还要重读

```
seq 84  doc_new → "已记入本会话的已读集合"
seq 94  edit    → 成功
seq 99  edit    → ❌ 被拒（重读）
...
seq 149 read(窗口)
seq 154 doc_mark → ❌ 被拒（重读）
seq 164 doc_mark → 成功
```

工具自己的文案说"已记入已读集合"，但**模型随后做的每一次 edit 都会让这份记录失效**。
对一份「刚由我自己创建、只有我知道内容」的文档，这个约束的收益几乎为零。

### 5.2 H-6 只报 warn，于是形成"永远追不上"的循环

```
seq 154/164 标绿 → seq 182 H-6 报出 → 改 read-order
→ seq 222 H-6 又报出 → 改 handover
→ seq 288 H-6 还在报 → 放弃
```

H-6 报的是真的（标绿后确实改了被引用文档），但它在**结构上无法被满足**：
交接要写"现在到哪了"，而写完之后**必然**还要改别的文档。
这与已删除的 H10 是同一类问题——**"永远无法满足的警告会让所有警告都变得可疑"**。

### 5.3 「只读片段不算读过」从没写进模型能看见的地方

这就是我今天修的那条（见 §6）。本轮 6 次窗口读，**5 次撞墙**，
而注入块里只说了"改过的文档会变回未读"，**没说过片段读根本不算**。
