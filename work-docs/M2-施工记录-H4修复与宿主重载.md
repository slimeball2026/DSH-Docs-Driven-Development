# M2 施工：宿主重载方法与 H4 修复记录

> 这份文档记录两件**实测**得出的事实，以及 M2 开工前已完成的第一刀。
> **它不是交接文档**（`role: evidence`），不参与 H1–H7 校验。

## 一、改完代码怎么让运行中的宿主用上（**交接 §0.6 需要订正**）

交接 §0.6 写的是「改 JS/TS 必须重启 DSH —— 模块不会热替换」。
**前半句对，后半句的结论不对**：不必重启，有更便宜的办法。

### 1.1 实测方法与结果

我用一个只做探测的临时 DDD 项目（`_m2-probe`，已删）做了 A/B 对照：

| 步骤 | 动作 | 观察 |
|---|---|---|
| 1 | 把会话工作目录切到探针项目 | 索引块出现，插件激活（说明 S1 按项目激活正常） |
| 2 | 调 `doc_handover_check` 查一份**只用中文证据**的交接 | **被 H4 拒**：「有 3/3 条没有证据形式」 |
| 3 | `plugin_manager set_bundle @local/ddd enabled=false` | 索引块消失（开关确实生效） |
| 4 | `plugin_manager set_bundle @local/ddd enabled=true` | 索引块回来 |
| 5 | 同一份交接再查 | **通过**（只剩 H9 提醒） |
| 6 | 再查一份证据为「看起来没问题」的交接 | 被拒，且**拒绝文案带上了新加的样例** `seq=42`、`3/3 通过` |

**第 2 步与第 5 步是同一份文档、同一个工具、同一个会话**，中间只做了一次停用/启用。
结论：**`plugin_manager` 的 disable → enable 会重新加载插件模块。**

### 1.2 为什么这很重要

- 交接说「改 JS/TS 必须重启 DSH」，而 M2 的施工者**正运行在 DSH 会话里** ——
  重启等于终止自己，会让每一步验证都变成跨会话的往返。
- 有了这条，M2 的验证链是：**改代码 → build（若 client）→ 停用/启用 bundle → 浏览器硬刷新 → 验**。
- 它**没有取消**交接 §14 的另一半：client bundle 仍有两层缓存（host `/plugins` 路由 + 浏览器），
  **硬刷新仍然必要**。host 侧的停用/启用只解决「host 模块」那一层。

### 1.3 边界（别把它当万能）

- 这是**实测**，不是文档承诺；宿主升级后可能变。每次 M2 验收都应当顺手复验一次。
- 它只对**插件模块**有效。改 `package.json` 的 `dsh.client` 声明或新增文件后，
  第一次仍建议重启一次，因为 `/plugins` 路由的 bundle 组合表可能被缓存（SPEC §14 的第一层缓存）。
- **`cordis.patch.yml` 的改动**走的是另一条路径（profile patch 层），本条不覆盖。

### 2.2 我先写测试，然后**验证测试真的会红**

SPEC §9.5 要求「先写这 7 条测试，再改正则」。我照做了，但过程中发现**我自己的测试有两处是假的**：

| 我第一版写的断言 | 为什么是假的 | 怎么修 |
|---|---|---|
| `hasEvidence('单测 722/722 全绿')` | 被同一数组里 `单测\s*\d+\s*\/\s*\d+` 那条分支命中，**在 bug 版本上也是绿的** | 改成裸分数 `722/722 全绿` |
| 端到端 §5 用了 `node --test` / `seq=` 作证据 | 那两条分支本来就工作，整段**在 bug 版本上也能过 H4** | §5 三条证据全部改成纯中文 `N/N 全绿` |

**这是我接手后第一件「判断题」的第一个答案**：复核者写的测试可能「刚好能让变异变红」，
而我写的第一版也有同样的毛病。**只有把修复回退掉、看测试是否变红，才能证明测试有效。**

### 2.4 顺带修的一个真问题

`_rv/ddd-bundle` 是 `ddd-bundle` 的**整份副本**，`_rv/mutate.mjs` 只改副本。
改完 `ddd-bundle` 后**必须同步副本**，否则变异测试测的是旧代码。
本次已同步，并用 SHA256 逐文件核对：**75 文件 IN SYNC**。
