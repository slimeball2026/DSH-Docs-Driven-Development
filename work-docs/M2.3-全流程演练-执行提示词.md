# 全流程演练 · 执行提示词（M2.3 之后版）

> **用途**：在一个**全新工作区**里，从零跑一次
> **立项 → 按文档施工 → 交接 → 新会话接续**，并在**真实 UI** 上看一遍。
>
> **与 `M1.5-无UI全流程演练-执行提示词.md` 的区别**：
> 那一版跑在**没有 UI** 的 M1.5 上，验的是"没有 UI 时主流程走不走得通"。
> 这一版跑在 **M2.3 之后**：UI 已经在（左栏入口、主栏整页、会话右栏页签、AI 阅读顺序条），
> 所以要验的是「**人**能不能看见 AI 在干什么」，而不只是"工具能不能调通"。

---

## 0. 读之前：这次演练能验到什么、验不到什么

### 能验到

| 环节 | 为什么值得验 |
|---|---|
| **从零立项** | 真实项目从空目录开始，而不是手工摆好的夹具 |
| **首轮门禁拒绝** | `【门禁】0/N` → 写被拒 → 读完放行，在真项目上的第一次 |
| **中途改文档** | 指纹变化 → 需要重读，且有真实上下文干扰 |
| **交接落定** | `doc_new` → `doc_handover_check` → `doc_mark authoritative` |
| **新会话接续** | 索引块 + 交接 → 能否复述"这是什么、到哪了、下一步" |
| **🆕 UI 可见性** | 左栏入口 / 主栏整页 / **会话右栏页签** / **AI 阅读顺序条** |
| **🆕 看板 `下一步` / `依据文档`** | M2.3 刚补上真源，**从没在真界面看过** |
| **🆕 右栏页签的会话切换** | 切到新会话不炸、切回能恢复（这是上次事故的核心判据） |

### 验不到（**别指望它**）

| 项 | 为什么 |
|---|---|
| 归档闭环的 UI 半侧 | 需要人勾选 + 点按钮，本演练不安排 |
| 坟场同名/子目录 | **用户已拍板：不做这个功能** |
| 子代理边界（N9） | 不派子代理 |
| 多份交接的链（H6/H7 完整形态） | 这次只有一份交接 |

## 1. 开工前：用户要做的事（3 分钟）

1. **建一个全新的空目录**，例如
   `C:\Users\slimeball\Documents\deepseek-harness\DDD演练-全流程\`
   > ⚠️ **不要**在 `DDD插件施工` 里面建（那里根目录不是 DDD 项目，且有大量夹具会互相干扰）。
2. **在这个目录里新开一个 DSH 会话**（工作区选它）。
3. 把下面 §2 的提示词**整段复制**给这个会话。
4. 第一个会话做完后，**在同一个目录再开一个全新会话**（不要续话），把 §3 的提示词给它。
5. 两个会话都跑完后，回第一个会话（或任意会话）把 §4 的**人眼检查清单**走一遍。

## 2. 第一个会话的提示词（立项 → 施工 → 交接）

> 下面分隔线之间的内容，**整段复制**。

---

````
你是「文档驱动开发」（DDD）插件的一次**全流程演练**的执行者。
工作区是一个全新的空目录。你的任务：从零立一个项目，做一件小事，然后写交接。

# 这个项目是什么（先读这段，它决定你怎么写文档）

DDD 是一个 DSH 插件：**AI 在改项目文档之前，必须先读过该读的文档**。
「读没读」由插件记账，并在工具调用时用代码里的 `if` 强制 —— 不是靠提示词提醒。
它只在**带激活标记的项目**里生效；没有标记，整个插件对你的项目 no-op。

# 纪律（贯穿全程）

- **贴原文**。我要工具返回的**逐字文本**，不是你的总结。
- **被拒绝是正常的，被拒绝也是证据**。不要为了顺利而绕路。
- **不要修改 `AGENTS.md`**（它是激活标记）。
- **不要建 `docs/` 以外的目录**，除非某一步明确要求。
- 如果某一步**和你预期的不一样**，照实际记录，**不要自己修正**。

## 第 0 步：先看环境（不要跳过）

1. 用 `pwsh` 跑 `Get-ChildItem -Force`，确认目录是空的（或只有无关文件）。
2. 告诉我结果。

**此时你会注意到**：你的上下文里**没有** `【门禁】` / `【项目】` 这些行，
而且 `doc_` 开头的工具（`doc_new` / `doc_mark` / `doc_handover_check` / `doc_health`）**不存在**。
**这是正确的** —— 项目还没激活。下一步解决它。

## 第 1 步：写激活标记

用 `write` 创建 `AGENTS.md`，内容**逐字**如下（`<!-- ddd:index -->` 这一行必须有）：

```

<!-- ddd:index -->

这是一个 DDD 全流程演练项目。它可以被随便改。
```

**预期**：`write` 成功（插件还没激活，所以不会被拦）。

## 第 2 步：等标记生效

用 `pwsh` 跑 `Start-Sleep -Seconds 3`，然后做任意一次读取（比如 `Get-ChildItem docs`）。

**预期**：从下一次工具调用开始，你的上下文里会出现 `【门禁】` 行。
**如果没出现**，立刻停下来告诉我，不要继续。

- `title`: `00 · 阅读顺序`

# 00 · 阅读顺序

这个项目是「**把一份日志文件整理成 Markdown 报告**」的小工具。

## 约定

> **此刻请注意你的上下文**：`【门禁】` 应该变成 `0/1`（一份必读，还没读）。

> 所以很可能已经是 `1/1`。**两种都正常，如实记录**。

## 第 4 步：建施工图

- `role`: `spec`

- `summary`: `三个切片：读日志 / 生成 Markdown / 交给用户`

- `status`: `authoritative`

## 目标

把 `input.log` 整理成一份 `report.md`。

| 切片 | 内容 | 状态 |

| S2 | 生成 Markdown 报告 | 未开始 |
| S3 | 把报告交给用户 | 未开始 |

## 边界

- **不做**日志分析、不做可视化。

## 第 5 步：做第一件"施工"

1. 用 `write` 创建 `input.log`，内容：

```
2026-11-14 08:00:01 INFO  启动
2026-11-14 08:00:05 WARN  磁盘剩余 12%
2026-11-14 08:00:09 ERROR 写入失败
```

2. 用 `write` 创建 `report.md`，把上面三行整理成一张 Markdown 表格
   （表头：时间 / 级别 / 消息）。

**预期**：两次 `write` 都**成功**。

> ⚠️ **不要期待被拒**。`report.md` 是新文件，注册表还不认识它，
> 而门禁对"注册表里没有的 docs/ 文件"是**放行**的（`core/gate.js`，M0 既有行为）。
> 真正的门禁拒绝发生在**改已存在的必读文档**上，见第 5b 步。

## 第 5b 步：验一次**真正的门禁拒绝**（重要）

先做一件事：**不要读任何文档**，直接用 `edit` 改 `docs/spec-report.md` 里已有的内容
（比如把切片表里 S3 那一行的「未开始」改成「进行中」）。

**预期（两种情况都要如实记录）**：

- **如果被拒**：文案里会有「必须先读」。**把原文贴出来** —— 这是门禁生效的证据。
- **如果没被拒**：说明你已读过（`doc_new` 会把新文档记进已读）。
  那就再试一次改 `docs/read-order.md`，看是否被拒。

> **这一条是本次演练最有价值的观测点之一**。两种结果都有信息量。

## 第 6 步：中途改一次文档（验指纹）

1. 用 `edit` 给 `docs/spec-report.md` 的「## 边界」下面**追加一行**：

   `- **不做**字段重命名（原始英文级别保持小写）。`

2. 改完之后，**观察你的上下文里 `【门禁】` 的数字有没有变**。
   指纹变了 = 已读失效 = 可能退回未读。**把观察结果如实写下来。**

## 第 7 步：自检

1. 用 `doc_health` 跑一次，把**完整输出**贴出来。
2. 用 `doc_handover_check` 试一次（此时还没有交接，它应该报"没有交接文档"）。
   把原文贴出来 —— **这是预期行为**。

## 第 8 步：写交接

用 `doc_new` 建一份 **`role: handover`** 的文档：

- `role`: `handover`
- `id`: `handover-001`
- `title`: `02 · 交接 · 给下一位`
- `summary`: `S1/S2 做完、S3 未开始、下一步做什么`
- `basis`: `实测`
- `body`: **必须包含七段**（缺一段会被校验拒绝）

**七段的标题关键词**（用这些词做 `##` 标题，判据才认）：

| # | 标题要含 | 要求 |
|---|---|---|
| 1 | 意图 / 为什么 | 非空说明（不能写「无」） |
| 2 | 现在到哪了 / 现状 / 到哪了 | 至少 1 个表格行或列表项 |
| 3 | 下一刀 / 下一步 / 接下来 | 至少 1 条**含具体路径 / 工具名 / 命令** |
| 4 | 坑 / 不要重犯 | 至少 1 个表格行 |
| 5 | 验收 | **每条都要带证据形式**（见下） |
| 6 | 刻意没做 / 负向范围 / 没做的事 | 至少 1 个列表项 |
| 7 | 仍未决 / 需要拍板 / 已拍板 | 可为空，但必须显式写「无」 |

body 用下面这段（**§5 里那两处 `⚠️ 待填` 必须换成真实值**）：

```
# 02 · 交接 · 给下一位

## 1. 我的意图

这个项目的意图是**证明"把日志整理成报告"这件事能被文档驱动地做完**，
而不是写一个真实的日志分析工具。所以边界比功能重要。

## 2. 现在到哪了

| 切片 | 状态 | 说明 |
|---|---|---|
| S1 读日志 | 已完成 | `input.log` 已存在 |
| S2 生成报告 | 已完成 | `report.md` 已生成 |
| S3 交给用户 | 未开始 | 等用户确认格式 |

## 3. 下一刀

- 让用户确认 `report.md` 的表格格式（列的顺序、是否要合并同类行）
- 确认后用 `doc_mark` 把这份交接标成 `superseded`（如果还有下一份交接）

## 4. 坑

| # | 坑 |
|---|---|
| 1 | 施工图里原来漏了「不做字段重命名」这条边界，是我中途补的 |
| 2 | `input.log` 只能读不能改，改了就违反边界 |

## 5. 验收

- 本次会话 id：⚠️ 待填（把真实的会话 id 填进来，形如 `session-xxxxxxxx-...`）
- **边界**：`input.log` 的 sha256 = ⚠️ 待填
  （跑 `Get-FileHash input.log -Algorithm SHA256` 把真实的十六进制值填进来）
- **`report.md` 行数**：⚠️ 待填，写成 `4/4 通过` 这种形状
  （跑 `(Get-Content report.md).Count`，把结果填进 `N/N 通过` 里）

## 6. 刻意没做

- 没做日志分析（超出本项目边界）
- 没做样式美化（S3 之后再谈）
- 没改 `input.log`

## 7. 仍未决

- `report.md` 的列顺序要确认（时间-级别-消息 还是 级别-时间-消息）
```

> ⚠️ **§5 是 H4 判据的雷区，我实测了 6 种写法**（下面这些**不通过**）：
>
> | 写法 | 为什么不过 |
> |---|---|
> | `单测：本项目无代码，不适用` | 没有任何可核对的形式 |
> | `sha256 与创建时一致` | `sha256` 后面必须跟**真实十六进制**，光说"一致"不算 |
> | `report.md 是 4 行（1 行表头 + 3 行数据），逐行可核` | **「4 行」不是证据形式** |
> | `report.md 行数：4/4 行可核` | **`4/4 行可核` 不行** —— 分母后必须跟「通过 / 全绿 / passed」这类词 |
> | `report.md 共 4 行，4/4 可核` | 同上 |
> | `report.md 4/4 行可核` | 同上 |
>
> **实测能过的写法**（任选其一）：
>
> | 写法 | 命中的判据 |
> |---|---|
> | `会话 id：session-aea4f0e0-...` | 会话 id |
> | `sha256 = a1b2c3d4...`（真实值） | 哈希 |
> | `report.md 是 4 行：4/4 通过` | 测试输出（`N/M 通过`） |
> | `report.md 4 行（单测 4/4 全绿）` | 测试输出 |
> | `report.md 4 行（ALL GOOD）` | 测试输出 |
> | `seq=42` | 事件序号 |
>
> **最稳的三条组合**：**会话 id + 真实 sha256 + `N/N 通过`**。

**预期**：返回 `已创建 docs/handover-001.md（id: handover-001, order: -10）`
（交接的 order 自动取「最小 handover order − 10」，第一次是 `-10`）。

## 第 9 步：校验并落定交接（**顺序不能错**）

1. `doc_handover_check`，参数 `id`: `handover-001` → 把**完整返回**贴出来。
2. 如果 `ok:true`，用 `doc_mark` 把它标成 `authoritative`：

   - `status`: `authoritative`
3. 再跑一次 `doc_handover_check`，贴出返回。

**不标 authoritative，下一个会话的索引块里根本看不到这份交接** ——
那么"交接接续"会直接失败，而失败原因看起来像"插件坏了"。

## 第 10 步：报告

把上面的结果汇总，包含：
- 每一步的**工具返回原文**（不要总结成"成功了"）
- 哪些步骤被门禁**拒绝过**，拒绝文案是什么
- `doc_health` 的完整输出
- **第 6 步的观察**：改文档后 `【门禁】` 的数字变了吗

**最后**：把这份汇总完整贴回给用户。
````

## 4. 人眼检查清单（**UI 部分，AI 验不了**）

## 5. 如果失败了，怎么判断是"插件坏了"还是"提示词写坏了"

**先查提示词，再查环境，最后才怀疑插件。**

| 现象 | 真实原因 | 是不是缺陷 |
|---|---|---|
| 写 `docs/report.md` **没被拒** | 注册表不认识的新文件 → 放行（M0 既有行为） | ❌ 不是，是设计 |
| `doc_handover_check` 报 **H4** | §5 写了「不适用」或「与创建时一致」，没有证据形状 | ❌ 不是，body 写错了 |
| 新会话索引块**看不到** `handover-001` | 交接还是 `draft`，没 `doc_mark` 成 `authoritative` | ❌ 不是，漏了第 9 步 |
| `【门禁】` 一直不出现 | `AGENTS.md` 没写 `<!-- ddd:index -->`，或没等够 2 秒 | ❌ 不是，环境问题 |
| 右栏页签点开**一片空白** | 三处注册的 key 不一致（类型 / 正文 / 标题） | ⚠️ **可能是缺陷**，把控制台报错贴给我 |
| 右栏**整个变空**且切会话不恢复 | 渲染期抛错（上次是 hook 违规） | ⚠️ **是缺陷**，把控制台报错贴给我 |

**如果确实是插件问题**：把工具返回原文 + 控制台报错 + 工作区状态一起给我。

## 6. 一个提醒

**这次演练的产出不是"跑通了"，而是"哪里显示出断点"。**

M0–M2.3 的判据大多是**单点**的，而且很多在**手工摆好的夹具**上。
一个真实项目从零开始会遇到夹具里没有的东西 —— **那些才是这次要发现的**。

尤其这次多了 UI：**代码正确 ≠ 界面可用**。
上一轮我在同一件事上栽了两次（inject 没生效、页签把右栏炸空），
两次都是**用户点出来的**，不是我的测试。所以 §4 那 16 项请务必自己看。
