# M2.2 施工记录：client 半侧启用的真因

> **日期**：2026-11-13 ｜ **环境**：DSH desktop `0.2.2-rc.2`（commit `a6b1b85`）｜ GUI `http://127.0.0.1:59258`
> **结论**：M2 的「client 半侧未启用」**已解决**。真因是一行代码，不是组合失败、不是 inject 包名、不是版本问题。

---

## 1. 真因（一行）

`src/client/entry.tsx` 的 `wirePreview()`：

```js
const sidebarRight = ctx?.sidebarRight     // ← 就是这一行
```

**cordis 的 `ctx` 是 Proxy。读取一个没有写进插件 `inject` 的服务时，它不返回 `undefined`，而是直接抛：**

```
Error: cannot get property "sidebarRight" without inject
```

`?.` 完全拦不住 —— 抛错发生在**属性读取那一刻**，不是后续调用。

### 1.1 为什么会炸掉整个面板

```js
apply(ctx) {
  wirePreview(ctx)                              // ← 第一句就抛
  const { cwdOf, sessionIdOf } = sessionInfoOf(ctx)
  const controller = createController({ ... })
  return registerPanel(ctx, controller)         // ← 永远到不了
}
```

`apply()` 在**第一条语句**就抛 → `registerPanel` 永不执行 → 双注册不发生 → **面板不出现**。

### 1.2 症状有多难查（这条值得记住）

| 现象 | 会误导你去查什么 |
|---|---|
| `fiberPhase: active` | 以为插件加载失败 |
| factory 已注册（`duplicate factory registration`） | 以为 bundle 没下载 |
| `__DSH_BOOT__` 里有我们、batch 里有我们 | 以为宿主组合失败 |
| **crash 日志为空** | 以为 boot 没报错 |
| client `slots` 里没有我们 | 以为注册逻辑写错了 |

**全部指向错误方向。** 真正的答案是：加载全对，**`apply` 抛了**。

> 唯一能看到真因的地方是**浏览器控制台**：
> ```
> web boot: warning: 1 entry did not activate
> @local/ddd: failed: Error: cannot get property "sidebarRight" without inject
> ```
> 而它**不写 crash 日志**——因为 `@local/ddd` 不在前端的 required 集合（写死的 7 个官方包）里，
> 只走 `warning` 分支。

**教训：`fiberPhase: active` 只证明 entry 启动过，不证明 `apply()` 成功返回。**

## 2. 修复

### 2.1 抽出纯逻辑层 `src/client/entry-logic.ts`

新增文件，装三件事：`softService` / `sessionInfoOf` / `wirePreviewOf`。

为什么不在 `.tsx` 里改：**Node 的类型剥离不处理 JSX**，
`.tsx` 无法被单测 `import`（`ERR_UNKNOWN_FILE_EXTENSION`）。
想被测到的逻辑必须放 `.ts`。

### 2.2 软取统一走 `ctx.get(...)`

```ts
export function softService(ctx, name) {
  try {
    if (typeof ctx?.get !== 'function') return undefined
    return ctx.get(name)     // ← 正式软取接口，缺席返回 undefined 而不抛
  } catch {
    return undefined
  }
}
```

三处调用点全部改掉：`wirePreviewOf` 的 `sidebarRight`、`sessionInfoOf` 的 `layout` 与 `sessions`。

> ⚠️ `sessionInfoOf` 里原本还有 `ctx?.layout?.panelInfo?.()` —— **同一个坑**，
> `?.` 一样救不了。一并改掉。

### 2.3 `registerPanel` 的 `ctx?.slots` 也改

`slots` 虽在 `inject` 里、不会抛，但**保持同一条纪律**：
可选服务一律软取，将来 `inject` 变了也只是「面板不出现」而不是「apply 抛错」。

## 5. 顺带澄清的三条现场事实

1. **`/plugins` 端口探测返回 404 不代表路由不在**。桌面前端走 `dsh-app://`，
   HTTP 口只暴露部分路由。**别拿它当判据。**
   真正的判据是浏览器里的 `window.__DSH_BOOT__`。
2. **`plugin_manager.list_plugins` 的 `fiberPhase: active` 是 host Loader 树的状态**，
   不覆盖浏览器里那棵 client Loader 树。
3. **`logs/` 为空 ≠ 没出错**。`@local/ddd` 这种非 required 条目失败只进 `warning`，
   不写 crash。**要看浏览器控制台。**
