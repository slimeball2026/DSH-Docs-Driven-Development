# DDD：文档接续与版本保护

候选版本：1.2.0-m4.4。用于 DeepSeek Harness 的项目级文档工作区。

DDD 提供当前交接入口、实时参考目录和目标文档的版本保护。新会话先读交接，再按任务选择依据；不要求把全部有效文档读完才工作。用户可在 DDD 面板浏览文档、交付物、归档与恢复。

## 日常使用

- 用户在面板初始化一个工作区后，插件才对该项目生效。普通项目不受影响。
- `doc_new` 生成 frontmatter 并刷新目录。中文标题显式给 `id`。默认创建 draft。
- `doc_mark` 修改状态或 basis；正文和其他结构字段用 `edit`。
- 用 `doc_new(role: handover, status: authoritative, ...)` 一次发布当前交接。显式 draft 保留草稿，需选为入口时用 `doc_mark` 发布。
- 发布只表示当前选用的接续入口，不表示任务全部完成。之后继续工作、发现漏项、原地编辑交接均为正常路径，无需重新发布。
- 一条决定只更新实际归属文档，不默认同步所有规格、索引和旧交接。
- `doc_health` 与 `doc_handover_check` 是可选只读诊断，不验证语义真实性或工作完成情况，也不是交接前置。

交接说明截至本次记录的状态、后续动作（可以是无）、关键约束与实际验证范围。无需固定七段或特定证据词形；没有测试就如实说明。

## 版本保护与边界

修改受管目标前先读取它；外部修改后需重读。同会话成功自改后可继续，不因自身版本变化反复读全文。发布写入使用文件版本条件并对失败做有条件恢复，不覆盖其他会话的改动；跨文件发布不承诺操作系统级原子事务，部分失败会明确报告恢复路径。

frontmatter 是元数据真源。目录由注册表实时派生，面板保留完整文档和阅读记录。旧入口文件里的手写清单或 M3 自动块原样保留，但不再自动回写，可能滞后；按实时目录找到当前交接。升级不自动迁移或清空用户正文。AGENTS 只更新插件受管块，块外内容保留。

子代理文档写入限制、decision 仅追加、evidence/instruction 保护、坟场隔离沿用原规则。归档工具只标 void，物理搬运和恢复由用户在面板确认；superseded 的旧交接无需再标 void。交付文件放 deliverables/ 后用宿主 present 呈现。Shell 任意命令写入不属于路径工具门禁能完整覆盖的范围。

## M4 精简内容

取消七段/H3/H4/H11 等正文措辞判定、H-5 的 basis/status 告警、H-6 全库标绿快照及健康检查写回。删除磁盘清单回写与交接登记副本。旧快照文件不会被读取或删除。authoritative 与依据类型分别表达入口选择和结论来源，basis 可省略。

保留四个工具名与主要输入；输出结构和诊断含义已更新。旧 handoverCheckStrict 配置退役。旧七段正文继续可读，面板可选解析其下一步，但不要求采用该格式。

## 开发与验证

开发目录为 ddd-bundle/。运行 `node --test --test-isolation=none`；构建客户端用 `pnpm run build`。界面加载构建后的 lib/client.js，修改客户端必须重建。M4 发布与失败恢复反例在 test/m40-publication.test.js；其他保留的回归覆盖目标读入、外部变化、子代理隔离、预览、交付、归档与恢复。

候选包安装通过 Harness 插件管理器进行。升级前保留 v1.1.0 包以回滚；不要在 profile 中手改依赖或 patch。候选版尚不代表公开发布。
