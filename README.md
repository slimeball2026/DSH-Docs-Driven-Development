# DDD：文档接续与版本保护

**候选版本：1.2.0-m4.4** · DeepSeek Harness · MIT。此工作树是本地 M4 候选镜像，尚未公开发布。候选采用正常根目录布局（index.js / lib/client.js），不使用版本子路径。修正版候选已本机安装，46/46 个安装文件与归档一致；本版本尚未重启宿主或重跑真实会话，管理器报告已应用不能代替运行中行为确认。

DDD 帮助新会话找到当前交接，按任务查阅依据，并保护受管文档不被旧版本覆盖。它提供实时参考目录、文档预览、交付物、归档与恢复；不要求 AI 读完整个目录才开始工作。

## 开始使用

1. 通过 Harness 插件管理器安装可安装候选包。源码仓库中的 [plugin](plugin/) 保留 TypeScript 源码，直接打包前还需要客户端构建和 Host 转译；不要把此源码目录直接复制到 profile 的 node_modules。
2. 将配套的 [ddd-workflow 技能](skill/ddd-workflow/SKILL.md) 放入用户技能目录。它提供简短操作说明。
3. 在 DDD 面板选择项目，由用户点击“初始化为 DDD 工作区”。未激活项目不受影响。新入口只保存长期说明，不生成需要不断同步的磁盘清单。
4. 向 AI 描述任务；新会话先看当前交接，再按任务读取相关依据。

## 日常操作

| 需要做什么 | 对应操作 |
|---|---|
| 新建规格、决策或其他受管文档 | `doc_new` 生成 frontmatter；中文标题显式给 `id`，默认 draft。 |
| 修改正文 | 读取目标后用 `edit`；外部改动后重读，同会话成功自改后可继续。 |
| 修改状态 | `doc_mark`；其他结构字段用 `edit`。 |
| 交接 | 一次创建 `role: handover, status: authoritative`；显式 draft 不取代当前入口，需用作入口时再发布。 |
| 归档 | AI 用 `doc_mark` 标 void 作提议，用户在面板确认物理搬运；superseded 无需再标 void。 |
| 交付 | 文件放入 deliverables/，用宿主 `present` 呈现。 |

交接写清截至本次记录的状态、后续动作（可以是无）、关键约束、实际验证范围及未验证内容。没有固定七段或证据词形。**发布表示选用当前接续入口，不表示工作全部完成。** 之后发现漏项可继续工作并原地修订，不需要撤回入口、新建交接或重新发布。

`doc_handover_check` 和 `doc_health` 保留为可选只读诊断；它们不认证语义真实性，也不判断任务是否完成，不是交接前置。

## 导航与界面

- 默认 AI 上下文仅提供当前交接（无已发布交接时退到项目入口）、必要安全警示和查找实时目录的方法。
- 面板保留完整文档目录；参考目录中的读取标记不等于全局写权限，用户点开预览不计作 AI 已读。
- frontmatter 是元数据真源。旧手写阅读清单和 M3 自动块原样保留，但不再自动回写，可能滞后；以实时目录为准。
- AGENTS 只更新插件受管块，块外用户指令保留。旧项目不自动批量迁移正文。

## 保留的保护

目标文档读取与版本检查、外部改动保护、decision 仅追加、evidence/instruction 保护、子代理文档写入边界和坟场隔离继续有效。发布事务检查文件版本并在失败时做有条件恢复，不覆盖其他会话的新改动。跨文件发布不承诺操作系统级原子事务；部分失败会给出真实状态和恢复路径。

Shell 任意命令写入不在路径工具门禁能够完整覆盖的范围。读取记录是会话内存状态，宿主重启会重建；UI 的曾读标记与当前版本权限应分别理解。

## M4 删除的维护负担

取消七段/H3/H4/H11 正文措辞判定、H-5 的 basis/status 告警、H-6 全库标绿快照及健康检查写回；删除磁盘清单回写与交接登记副本。旧快照文件停止读取，升级不会擅自删除。basis 可省略；权威入口与结论来源不再混为一个维度。旧七段交接仍可读取。

四个工具名及主要输入保留，输出结构和诊断含义已更新；旧 handoverCheckStrict 配置退役。升级前保留 v1.1.0 可安装包以便回滚。

## 开发与候选打包

[plugin](plugin/) 包含 Host、客户端源码、已构建客户端、测试和构建配置；[插件说明](plugin/README.md) 提供实现边界。历史 M1 记录单独保存在插件目录，不作为现行工序。

在 plugin/ 执行：

```powershell
node --test --test-isolation=none
pnpm run build
```

客户端实际加载 lib/client.js，修改 src/client/ 必须重建。此源码镜像继续保留 server/*.ts，与 v1.1.0 的源码发布方式相同；**可安装包**需在隔离 staging 中把 Host TypeScript 转成 JavaScript 并改写导入后缀，再校验装入 node_modules 后可加载。不得只改扩展名。

M4 发布、部分失败恢复、发布后继续修订的反例在测试中维护。当前候选的完整构建、安装和实机会话证据由施工验证记录提供，不能沿用 v1.1.0 的“18 项全绿”或历史测试数量作为本版证明。

本机热切换验证已停止：m4.1 的管理器应用结果未使实机会话出现新回执；m4.2 尝试版本子路径时受到旧 junction/realpath 缓存影响。m4.3 已恢复正常根目录布局，下一步应重启宿主清理缓存，再核对实际加载版本、短回执、当前入口及 UI。此前旧回执会话不算 M4 效率验收，也不据此宣称新实现无效。
